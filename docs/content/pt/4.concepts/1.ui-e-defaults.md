Toda camada visual de um campo tem nome, e todo nome pode ser sobrescrito. Esta
página mostra a cadeia inteira: o que o componente declara, o que o seu arquivo
de defaults muda e o que a prop no call site decide.

## A cadeia de precedência

Os três entram no mesmo `merger`, nesta ordem — e quem chega depois manda:

| # | quando | o quê |
|---|---|---|
| 1 | componente | `defineDefaults` — o `ui` e o `default` que o `RText` declara no próprio arquivo |
| 2 | projeto | `app/rform/defaults.ts` — `defineFieldDefaults`, por nome de componente e por Util |
| 3 | campo | `:ui="{ … }"` — a prop no call site. Última na fila, então é a que decide |

## ui no call site

A prop `ui` é um `DeepPartial`: você escreve só a camada que quer mudar. E quem
junta as classes é o **tailwind-merge**, então `p-6` substitui o `p-3` do default
sem levar embora o resto da camada — o anel de foco continua ali.

## null apaga a camada

`undefined` significa "não passei", e é ignorado. `null` é explícito: zera as
classes daquela camada. String vazia não serve, porque o tailwind-merge junta e o
default sobrevive.

::demo{src="Ui/ui-null" title="null, e null seguido de classe nova" ui="grid gap-4 md:grid-cols-2"}
::

::callout{type="warn"}
Hoje isso exige um cast: o `mergerUI` entende `null`, mas o tipo de `ui` só
admite `string | undefined`.
::

## ui.Utils — o campo mandando no Util

`Label`, `Placeholder`, `Description`, `Error`, `Length` e `Loading` são
componentes à parte, com `defaults` próprios. O bloco `Utils` dentro do `ui` do
campo alcança cada um deles, e só naquele campo.

## app/rform/defaults.ts

Um arquivo, opcional, chaveado por nome de componente: é onde o projeto decide
como todo `RText` se parece, sem repetir prop em campo nenhum. O bloco `Utils`
no topo faz o mesmo para os sub-componentes, globalmente.

```ts
import { defineFieldDefaults } from "#rform/utils";

export default defineFieldDefaults({
    Text: {
        ui: {
            container: "gap-2",
            group: {
                field: {
                    input: "p-4 text-base"
                }
            }
        },
        default: ""
    },
    Utils: {
        Placeholder: {
            ui: {
                default: "text-xs"
            }
        }
    }
});
```

O módulo gera um template vazio quando o arquivo não existe — então criar depois
funciona, e este site roda **sem** ele de propósito, para as páginas mostrarem o
default de verdade.

### Quatro coisas que mordem

- **tailwind-merge, não concatenação.** Classe nova só remove a antiga quando as
  duas brigam pela mesma propriedade. Passar `p-6` troca o padding e mantém o
  resto da camada.
- **`null` zera, `undefined` ignora.** `undefined` é "não passei" e é pulado pelo
  merger; `null` é explícito e apaga as classes da camada.
- **`Utils` global × `ui.Utils` do campo.** `Utils` no topo do arquivo vale para
  todo mundo; `ui.Utils` dentro de um campo vale só ali — e ganha do global.
- **O nome do helper é acordo, não detalhe.** `defineFieldDefaults` está escrito
  no `oxlint.config.ts` e no `.vscode/settings.json`. Renomear sem mexer nos dois
  faz o lint de classe e o IntelliSense pararem **calados** dentro do arquivo.

## Do outro lado: defineDefaults

É o que cada componente do módulo chama para declarar o que você acabou de
sobrescrever: o `ui` completo mais o valor inicial do model. O
`Element<typeof defaults>` tipa as props a partir daí — é por isso que o tipo de
`modelValue` sai do `default`.

```ts
export const defaults = defineDefaults({
    ui: {
        container: "flex w-full flex-col gap-1",
        group: {
            wrapper: {
                container: "relative z-0 flex w-full flex-row items-center rounded-xl …",
                leading: "p-3 pr-0 flex",
                trailing: "p-3 pl-0 flex"
            },
            field: {
                container: "relative grow",
                input: "w-full rounded-lg bg-transparent outline-none p-3"
            }
        }
    },
    default: ""
});

export type Props = Element<typeof defaults, "text"> & Utils["Placeholder"] & Utils["Error"];
```

O `container` da raiz é `w-full`, não `grow`. O pai natural de um campo é o
`RForm`, que é coluna, e crescer ali é crescer na **altura**: num painel de altura
fixa, cada campo ganharia um vão vazio embaixo. Para um campo que deve ocupar a
altura que sobra, peça no call site — `:ui="{ container: 'grow' }"`, que o
tailwind-merge soma ao `w-full`.

## As classes-gancho

Todo campo e todo util — embutido **e** seu — carrega duas classes na raiz:

| raiz | genérica | específica |
|---|---|---|
| `fields/`, `app/rform/fields` | `RField` | `R<Nome>` — `RField RText` |
| `utils/`, `app/rform/utils` | `RUtil` | `RUtils<Nome>` — `RUtil RUtilsPlaceholder` |

A específica espelha a tag que você escreve. Elas são o alvo dos resets do
módulo — e por isso não dependem de haver um `RForm` no ancestral.

Quem as escreve é `hookUi`, **depois** do merge: `ui` é sobrescrevível por
contrato, e um gancho declarado nos `defaults` iria embora junto com um
`ui: { container: null }`.
