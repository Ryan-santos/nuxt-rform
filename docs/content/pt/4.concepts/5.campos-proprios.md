Um arquivo `.vue` em `app/rform/fields` é um campo de **primeira classe**: ganha
tag com prefixo `R`, entra no `FieldType` (então o `useRForm` aceita `type`), no
`Components` (então o `defineFieldDefaults` tipa) e pode ser alvo do `available`
de um preset. `app/rform/utils` faz o mesmo para os pedaços internos do campo.

## Um campo que o módulo não tem

```vue
<template>
    <div :class="props.ui?.container">
        <RUtilsLabel />

        <div :class="props.ui?.group">
            <button
                v-for="star in props.max"
                :key="star"
                type="button"
                :class="[
                    props.ui?.star?.base,
                    star <= current ? props.ui?.star?.on : props.ui?.star?.off
                ]"
                @click="model = star"
            >
                <Icon name="fa6-solid:star" />
            </button>
        </div>

        <RUtilsHint />
        <RUtilsDescription />
        <RUtilsError />
    </div>
</template>

<script lang="ts">
    import { computed } from "vue";

    import { useField } from "#rform/composables";
    import type { Element } from "#rform/types";
    import type Utils from "#rform/types/components/utils/props";
    import { defineDefaults } from "#rform/utils";

    export const defaults = defineDefaults({
        ui: {
            container: "flex grow flex-col gap-1",
            group: "flex w-fit flex-row gap-1 rounded-xl bg-background-100 p-2",
            star: {
                base: "cursor-pointer rounded-md p-1 text-xl transition-colors",
                on: "text-warn",
                off: "text-contrast/20 hover:text-contrast/40"
            }
        },
        default: 0,
        max: 5
    });

    export type Props = Element<typeof defaults, "rating"> &
        Utils["Label"] &
        Utils["Description"] &
        Utils["Error"] &
        Utils["Hint"] & {
            max?: number;
        };
</script>

<script setup lang="ts">
    const _props = withDefaults(defineProps<Props>(), {
        required: undefined,
        loading: undefined
    });

    const { model, props } = await useField(_props);

    const current = computed(() => Number(model.value ?? 0));
</script>
```

Daí em diante ele é um campo como qualquer outro — `name`, `rule`, `label`, `ui`
e model funcionam sem nada a mais.

## Um util que o módulo não tem

`app/rform/utils/Hint.vue` vira `RUtilsHint` e enxerga as props do campo pai pelo
`useUtil`, igual ao `RUtilsError`. O `Rating` acima o renderiza, então a prop
`hint` passa a existir em qualquer campo que o inclua.

```vue
<script lang="ts">
    import { useUtil } from "#rform/composables";
    import type { DeepPartial } from "#rform/types";
    import { defineDefaults, icon } from "#rform/utils";

    export const defaults = defineDefaults({
        hint: "",
        ui: {
            container: "ml-1 flex flex-row items-center gap-1 text-xs text-current/50",
            icon: { name: icon("alert"), class: "shrink-0" }
        }
    });

    export type Props = {
        hint?: string;
        ui?: DeepPartial<typeof defaults.ui>;
    };
</script>

<script setup lang="ts">
    const { props } = useUtil<Props>(defaults);
</script>
```

::demo{src="Customizados/util-novo" title="RUtilsHint, um util do app"}
::

O `icon` de `#rform/utils` é o que faz o `alert` daqui ser o **mesmo** ícone que o
`RUtilsError` usa — e acompanhar o override que o app tenha feito nele. Para um
ícone que só é seu, escreva o nome do iconify direto, como o `Rating` faz com
`fa6-solid:star`. Ver [Tema](/pt/concepts/tema#nos-seus-próprios-campos).

## No schema do useRForm

Como o campo entra no `FieldType`, ele é um `type` válido no schema — e o
`RDynamic` o monta sozinho, sem nenhuma tag escrita à mão.

## No defineFieldDefaults

`app/rform/defaults.ts` é tipado a partir do mesmo `Components`, então o campo
novo aparece nele com autocomplete:

```ts
import { defineFieldDefaults } from "#rform/utils";

export default defineFieldDefaults({
    Rating: {
        max: 10,
        ui: { star: { on: "text-primary" } }
    },
    Utils: {
        Hint: { ui: { container: "text-[10px]" } }
    }
});
```

## Substituindo um embutido

**Mesmo nome substitui o embutido inteiro** — mesma precedência dos presets. Para
**embrulhar** em vez de reescrever, o original continua alcançável pelo alias
`#rform/builtin`:

```ts
import Base, { defaults as base } from "#rform/builtin/fields/Text.vue";
```

::callout{type="warn"}
`Form` e `Dynamic` são nomes **reservados**. Um `app/rform/fields/Form.vue` falha
o build nomeando o arquivo.
::

## Regras do arquivo

- Nome PascalCase alfanumérico — ele vira chave de objeto **e** membro do
  `FieldType`.
- `<script>` exporta `defaults` (via `defineDefaults`) e o tipo `Props`.
- Campo chama `await useField(_props)`; util chama `useUtil<Props>(defaults)`.
- Containers (que aceitam filhos) também chamam `useProvide({ id, model })`.
- Um `<input>`/`<textarea>` nativo liga por `:value` + `@input`, **nunca por
  `v-model`** — ver abaixo.

## O elemento nativo liga por `:value` + `@input`

```vue
<template>
    <input
        :value="model"
        @input="model = inputValue($event)"
    />
    <input
        type="checkbox"
        :checked="model"
        @change="model = inputChecked($event)"
    />
</template>
```

`inputValue` e `inputChecked` vêm de `#rform/utils` e só escondem o cast do
`$event.target`. O motivo de não ser `v-model`: o `mounted` da diretiva é um
efeito pós-render que um `<Suspense>` ainda pendente represa — a página do
`NuxtPage` com um `useFetch` `lazy` preenchendo o model, por exemplo. Ao
resolver, ele reaplica o valor da **montagem** por cima do que chegou no meio, e
o campo aparece vazio com o model certo. Com `:value` o valor é prop, patchada
no lugar, sem hook adiado. Todos os campos embutidos são escritos assim.
