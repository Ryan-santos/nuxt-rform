O rform declara o `@nuxt/icon` como dependência de módulo e desenha todo ícone por
um **alias** sob o namespace `rform:`. Cor e radius são variável
([Tema](/pt/concepts/tema)); ícone é alias.

## A base

Os 20 aliases que o módulo registra, com o ícone do iconify para onde cada um aponta.
A tabela é lida da config do `@nuxt/icon` em runtime, então é sempre a lista real:

O `rform:image` é oferecido ao app sem nenhum componente do módulo usar.

## Trocar no app inteiro

**Trocar um ícone no app inteiro é sobrescrever o alias**, no `nuxt.config` (num
componente ou numa tag só é a prop [`icons`](#por-componente-ou-por-tag), adiante):

```ts
export default defineNuxtConfig({
    modules: ["nuxt-rform"],
    icon: {
        aliases: {
            "rform:calendar": "lucide:calendar",
            "rform:remove": "lucide:trash-2"
        }
    }
});
```

::callout{type="tip"}
Sobrescrever um alias **não derruba os outros 19**: o merge do Nuxt é fundo, chave
a chave, e o seu valor ganha só na chave que você escreveu. Escreva um, os dezenove
continuam de pé.
::

O namespace é o que mantém os dois lados separados. Os aliases já foram os nomes
curtos (`plus`, `calendar`…), e ali instalar o rform passava a definir 16 aliases
**no seu app** — um `<Icon name="plus" />` numa página sua resolvia para o ícone que
o módulo escolheu, e um alias `calendar` seu **trocava** o ícone do `RDate` sem
ninguém pedir.

## Por componente ou por tag

O alias vale para o app inteiro, e para todo componente que usa aquele ícone. Todo
campo e todo util que desenha ícone tem também a prop `icons`, e ela é chaveada pelo
**papel** do ícone, não pelo desenho: o `RNumber` tem `decrement` e `increment`, e
não `minus` e `plus`. O valor é o nome do iconify, cru.

São três camadas, e a de baixo vence:

| camada                                            | alcance                              |
| ------------------------------------------------- | ------------------------------------ |
| o `defaults.icons` do componente                  | o padrão, que lê os aliases `rform:` |
| `defineFieldDefaults`, em `app/rform/defaults.ts` | aquele componente, no app inteiro    |
| a prop na tag                                     | aquela tag só                        |

```ts
// app/rform/defaults.ts
import { defineFieldDefaults } from "#rform/utils";

export default defineFieldDefaults({
    Number: { icons: { increment: "lucide:plus", decrement: "lucide:minus" } },
    Utils: { Error: { icons: { alert: "lucide:circle-alert" } } }
});
```

```vue
<template>
    <RNumber
        name="quantidade"
        :icons="{ increment: 'lucide:circle-plus' }"
    />
</template>
```

Um papel que você não escreve continua com o padrão, e `""` deixa aquele papel sem
ícone — `Utils: { Error: { icons: { alert: "" } } }` tira o ícone de toda mensagem
de erro.

**Num campo, `icons` tem a forma do `ui`**: os papéis do próprio campo no topo,
e os dos utils que ele renderiza sob `Utils.<Nome>`. É dali, e só dali, que o util
lê — então
`<RText :icons="{ Utils: { Error: { alert: 'lucide:circle-alert' } } }">` troca o
ícone de erro daquele campo. Um papel próprio nunca desce: o `loading` de um
`RSelect` é o do painel, e o spinner do `RUtilsLoading` dele é
`Utils.Loading.loading`. Um `alert` solto no `icons` de um campo não compila e não
faz nada.

Para o ícone de um util, são quatro camadas, e a de baixo vence:

| onde                                                                        | alcance                    |
| --------------------------------------------------------------------------- | -------------------------- |
| o `defaults.icons` do util                                                  | o padrão                   |
| `defineFieldDefaults({ Utils: { Error: { icons: { alert } } } })`           | aquele util, em todo campo |
| `defineFieldDefaults({ Text: { icons: { Utils: { Error: { alert } } } } })` | aquele util, naquele campo |
| a prop na tag                                                               | aquela tag só              |

Os papéis de cada componente:

| componente       | papéis                                                         |
| ---------------- | -------------------------------------------------------------- |
| `RNumber`        | `decrement`, `increment`                                       |
| `RArray`         | `add`, `remove`                                                |
| `RCheckbox`      | `check`                                                        |
| `RDate`          | `calendar`, e `Utils.Calendar.prev`/`next`                     |
| `RSelect`        | `clear`, `toggle`, `search`, `loading`, `failed`               |
| `RFile`          | `upload`, `loading`, e `Utils.FileItem.*` para a linha         |
| `RSwitch`        | `on`, `off` (vazio por padrão), `loading`                      |
| `RPassword`      | `generate`, `show`, `hide`, `idle`, `pending`, `met`, `failed` |
| `RUtilsLoading`  | `loading`                                                      |
| `RUtilsError`    | `alert`                                                        |
| `RUtilsCalendar` | `prev`, `next`                                                 |
| `RUtilsFileItem` | `file`, `failed`, `retry`, `cancel`, `remove`                  |

::callout{type="warn"}
Duas formas antigas saíram. No `RSwitch`, o objeto `:icon="{ true, false, loading }"`
virou `:icons="{ on, off, loading }"`, e a prop `icon` saiu de vez — desligar o
indicador é `""` nos três papéis, `:icons="{ on: '', off: '', loading: '' }"`.
No `RUtilsError`, o `ui.icon.name` virou
`icons.alert`, e o `ui.icon` passou a ser a string de classe que antes era
`ui.icon.class`.
::

## Nos seus próprios campos

Num `.vue` de `app/rform/fields` ou `app/rform/utils` você escreve o nome do iconify
direto, como em qualquer componente Vue. Mas se o ícone é um dos 20, escreva o
**alias**: além de não repetir o nome, ele **acompanha o override** que o app tenha
feito.

```vue
<template>
    <Icon name="rform:alert" />
    <Icon name="fa6-solid:star" />
</template>
```

Para o seu componente ganhar a prop `icons`, ele segue a mesma convenção dos
embutidos: o `defaults.icons` declara os papéis, o `Props` intersecciona
`IconsProp<typeof defaults.icons>`, e o template lê `props.icons.<papel>`. Daí as
três camadas e a herança pelos utils saem de graça.

No `defaults.icons` o nome é **curto**, como a chave do `defaults.text`: o módulo
prefixa `rform:` sozinho, então `hint: "alert"` vira `rform:alert`. Nome com `:`
(`"lucide:star"`, ou o `"rform:alert"` por extenso) e `""` passam intactos. Só o
`defaults` do próprio componente é prefixado — o que o app escreve numa tag ou no
`defineFieldDefaults` continua sendo nome do iconify.

```vue
<template>
    <Icon :name="props.icons.hint" />
</template>

<script lang="ts">
    import type { DeepPartial, IconsProp } from "#rform/types";
    import { defineDefaults } from "#rform/utils";

    export const defaults = defineDefaults({
        ui: { icon: "shrink-0" },
        icons: { hint: "alert" }
    });

    export type Props = {
        ui?: DeepPartial<typeof defaults.ui>;
    } & IconsProp<typeof defaults.icons>;
</script>
```

O exemplo inteiro é o `RUtilsHint`, em
[Campos próprios](/pt/concepts/campos-proprios#um-util-que-o-módulo-não-tem).

::callout{type="warn"}
Nome que não é um dos 20 e não tem `:` renderiza **nada** — só um
`[Icon] failed to load icon` no console. É o modo de falha a conhecer: um
`hint: "plux"` com typo não quebra o build nem a lint, ele apaga o ícone.
::

## A guarda

`test/unit/icons.test.ts` cobre três casos, porque um nome errado não quebra build
nem lint — só apaga o ícone: (a) o
conjunto de nomes curtos nos `defaults.icons` dos componentes é **igual** ao dos aliases declarados,
nos dois sentidos; (b) nenhum nome estático sem `:` sobrou num template — que é
exatamente o que apagou quatro ícones quando o namespace entrou; (c) o prefixo que o
runtime aplica e o nome curto do módulo são a mesma string.
