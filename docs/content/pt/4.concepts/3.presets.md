Um arquivo = um preset. O nome vem do caminho relativo em camelCase:
`br/insc-est.ts` vira `brInscEst`.

- **Embutidos:** `src/runtime/presets/{rules,masks}/**/*.ts`.
- **Seus:** `app/rform/presets/{rules,masks}/**/*.ts`, recursivo. **Mesmo nome
  sobrescreve o embutido.**

## Masks

Tudo que é do Brasil mora em `br/` e vira `brAlgumaCoisa`. Não há mask genérica
hoje.

::demo{src="Presets/masks" title="as oito masks embutidas"}
::

Um nome que não bate com preset nenhum vai direto pro
[maska](https://beholdr.github.io/maska/) como pattern cru.

::callout{type="tip"}
Quem aplica a máscara é o [maska](https://beholdr.github.io/maska/): os tokens
(`#` dígito, `@` letra, `*` os dois), o `reversed`, o `eager` e o resto das
opções do `defineMask` são os dele, e a doc deles vale aqui sem tradução.
::

## Rules

Genéricas na raiz (`required`, `min`, `max`, `email`, `url`) e as do Brasil em
`br/`.

::demo{src="Presets/rules" title="as rules embutidas"}
Rode o submit.
::

::callout{type="tip"}
As rules embutidas **são** zod: cada uma monta um schema e devolve a primeira
issue como mensagem. E `rule` aceita um `ZodType` direto — então tudo que a doc
do [zod](https://zod.dev) descreve serve de validação aqui.
::

### Args nomeados no próprio ref

Não são posicionais:

```ts
rule="min"                              // preset sem arg obrigatório
:rule="{ name: 'min', min: 3 }"         // com arg
:rule="{ name: 'brInscEst', uf: 'SP' }" // preset seu, com arg
```

O tipo dos args sai do parâmetro da própria `validation`, então:

- preset sem args → aceita `"min"` e `{ name: "min" }`;
- preset com arg obrigatório → **só** `{ name, ...args }`, e faltar ou errar o
  tipo do arg é erro de compilação.

### min e max escolhem o schema pelo **valor**

Não pelo tipo do campo: com um número no model viram `z.number().min()`, com um
array `z.array().min()`, com uma string `z.string().min()`.

## Escrevendo o seu

```ts
// app/rform/presets/masks/dinheiro.ts
import { defineMask } from "#rform/utils";

export default defineMask({
    mask: "R$ ###.###,##",
    reversed: true
});
```

```ts
// app/rform/presets/rules/br/insc-est.ts
import { defineRule, type RuleContext } from "#rform/utils";

export default defineRule({
    available: ["text"],
    validation({ value, uf }: RuleContext<{ value: string; uf: string }>) {
        if (!value) {
            return;
        }

        if (value.length < 9) {
            return `Inscrição estadual de ${uf} inválida.`;
        }
    }
});
```

::demo{src="Presets/usuario" title="os dois em uso"}
::

Os helpers vêm de `#rform/utils` e **não** estão no auto-import — importe-os
explicitamente.

### available

`available` é `readonly FieldType[]`, então `["txt"]` falha na definição com
_Did you mean `"text"`?_ em vez de nunca casar com componente nenhum. É o filtro
que decide em quais campos o preset aparece.

### O contexto é um objeto só

Toda validação — de preset **ou** função inline no `rule` — recebe
`{ value, form, ...args }` e nada mais. Quem tipa é `RuleContext`:

```ts
RuleContext; // { value: unknown, form: … }
RuleContext<{ uf: string }>; // + o arg
RuleContext<{ value: string }>; // estreita o value: unknown & string = string
```

O tradutor **não** está no contexto: uma rule chega ao locale ativo pelo `trRule`
importado. Veja [Tradução](/pt/concepts/traducao#rules).

::callout{type="warn"}
`fromPreset` monta o contexto como `{ ...args, value, form }` — nessa ordem de
propósito, para um arg chamado `value` ou `form` não conseguir sombrear o que o
campo realmente tem.
::

## Nomes que colidem

Dois caminhos que colapsam no mesmo nome (`br/cpf.ts` + `brCpf.ts`) fazem o
build falar: `ERROR [rform] duplicate preset name`, nomeando os dois arquivos. O
Nuxt rebaixa falha de template a warning, então o `prepare` ainda sai com 0 — o
sintoma é o arquivo gerado sumir, não o build parar. Numa colisão de **mask** o
build para de verdade: o módulo importa `#rform/masks` estaticamente.

## Preset no useRForm

Um preset passa intacto por `normalizeSchema` (quem resolve é o campo) e vira
`z.any().superRefine(async …)` no `rules` agregado. Por isso **schema com preset
exige `safeParseAsync`**; schema só-zod continua síncrono.

Na prática o `safeParseAsync` deixou de ser trabalho do app: passe o `rules` em
[`<RForm :rules>`](/pt/form/form) e cada issue pousa no campo que a possui.
