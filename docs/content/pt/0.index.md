`rform` é um módulo Nuxt de formulários. Ele entrega treze campos prontos
(`RText`, `RSelect`, `RDate`, `RArray`…), um `RForm` que amarra todos eles a um
único model, e um `useRForm` que decide de onde vêm os tipos e a validação.

```vue
<template>
    <RForm v-model="data">
        <RText
            name="nome"
            label="Nome"
            required
            rule="required"
        />
        <RText
            name="cpf"
            label="CPF"
            mask="brCpf"
            rule="brCpf"
        />
    </RForm>
</template>

<script setup lang="ts">
    const { data } = useRForm<{ nome?: string; cpf?: string }>();
</script>
```

## Por que ele existe

Um formulário real tem quatro coisas que costumam morar em quatro lugares
diferentes: a **UI**, o **model**, os **tipos** e a **validação**. Quando elas se
separam, cada campo novo é quatro edições — e a que você esquecer não avisa.

Aqui elas se encontram no campo. `name` liga o campo ao model. `rule` liga o
campo à validação. `mask` liga o campo ao formato. E o tipo do `modelValue` sai
do `default` que o próprio componente declara.

## O que ele não faz

- **Não é um design system.** Toda classe do módulo é sobrescrevível por camada
  nomeada, e toda cor passa por uma variável `--rf-*`. Trocar tema é trocar
  variável.
- **Não inventa uma linguagem de validação.** `rule` aceita zod direto; os
  presets embutidos _são_ zod.
- **Não crava texto.** Nenhuma mensagem do módulo é literal — e num app com
  `@nuxtjs/i18n` o próprio módulo passa a falar pelo store do app.
