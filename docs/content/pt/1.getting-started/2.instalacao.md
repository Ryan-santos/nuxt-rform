## Instalar

```bash
pnpm add nuxt-rform zod
```

`zod` é peer dependency **obrigatória**: as rules embutidas são schemas zod, e
`#rform/presets` importa todas estaticamente. Esse barrel só entra por import
dinâmico, então zod fica fora do caminho crítico de uma página sem validação.

## Registrar o módulo

```ts
export default defineNuxtConfig({
    modules: ["nuxt-rform"]
});
```

::callout
O pacote no npm é **`nuxt-rform`** — o prefixo `nuxt-` é a convenção do
ecossistema, e é o que dá descoberta na busca. Tudo o mais continua curto: a
chave de config é `rform`, o alias é `#rform` e os seus arquivos moram em
`app/rform/`.
::

O rform declara `@nuxt/icon` como dependência de módulo e já registra os 16
aliases de ícone que usa, todos sob o namespace `rform:` — `rform:plus`,
`rform:remove`, `rform:loading`, `rform:calendar`… Não há nada a configurar ali, e
trocar um deles é [sobrescrever o alias](/pt/concepts/tema#os-ícones).

## O CSS

Uma linha no seu entry de Tailwind, e ela traz as duas coisas: o `@source` dos
componentes do módulo (o Tailwind não varre `node_modules`, então sem ele
nenhuma classe do módulo é emitida) e os tokens de tema.

```css
@import "tailwindcss";
@import "#rform/tailwindcss";
```

::callout{type="warn"}
Ponha `#rform/tailwindcss` **depois** de `tailwindcss`, como acima. A ordem
importa só quando os dois declaram a mesma variável, mas nessa ordem as cinco
formas de override funcionam — inclusive um `@theme` do app. Detalhes em
[Tema](/pt/concepts/tema).
::

Tem de ser um `@import` do seu entry, e nunca `nuxt.options.css`: num arquivo
que o Tailwind não trata como parte de um entry, o `@source` é ignorado e a
at-rule vaza crua para o browser.

### Sem Tailwind

Um app sem Tailwind não recebe token nenhum por essa via. Para esse caso o
pacote exporta o CSS pronto:

```ts
export default defineNuxtConfig({
    modules: ["nuxt-rform"],
    css: ["nuxt-rform/style.css"]
});
```

## Opções do módulo

```ts
export default defineNuxtConfig({
    modules: ["nuxt-rform"],

    rform: {
        // Idioma usado quando o app NÃO tem @nuxtjs/i18n.
        // Com ele instalado, quem manda é o locale dele — este valor não é lido.
        locale: "pt-BR"
    }
});
```

## O tsconfig do seu app

Um app Nuxt sem `tsconfig.json` na raiz acaba achando o tsconfig de um projeto
acima — e o `@vue/compiler-sfc` resolve `#rform/types/...` contra os tipos
gerados **daquele** projeto. O sintoma é mudo: as props que um util contribui
simplesmente não são declaradas, e um `<RRating hint="…">` cai como atributo de
fallthrough sem erro de compilação.
