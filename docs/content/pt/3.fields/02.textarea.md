## mask num textarea

Este é o campo que justifica a diretiva própria. A `v-maska` faz

```js
const a = e instanceof HTMLInputElement ? e : e.querySelector("input");
if (a == null || a?.type === "file") return;
```

— e um `<textarea>` cai fora dos dois ramos, então nunca é bindado. O
`MaskInput` do maska, porém, só usa `value`, `selectionStart`,
`setSelectionRange`, `addEventListener` e `dispatchEvent`, que um textarea tem:
só o guard exclui. O `vMask` do módulo instancia o `MaskInput` direto no
elemento, input **ou** textarea.

## Ícones

O campo não desenha ícone próprio; os da tabela são dos utils que ele renderiza.
Cada papel é uma chave da prop `icons`, e o valor é o nome do iconify. Os papéis
de um util ficam aninhados sob `Utils`, como no `ui`:
`:icons="{ Utils: { Error: { alert: 'lucide:circle-alert' } } }"`. Camadas,
`defineFieldDefaults` e o alias estão em
[Ícones](/pt/concepts/icones#por-componente-ou-por-tag).

| papel                   | padrão                                | onde aparece                             |
| ----------------------- | ------------------------------------- | ---------------------------------------- |
| `Utils.Loading.loading` | `rform:loading` → `eos-icons:loading` | o spinner do campo, com a prop `loading` |
| `Utils.Error.alert`     | `rform:alert` → `ooui:alert`          | ao lado da mensagem de erro              |
