O slot do `RArray` entrega `index`, e é ele que o filho usa como `name` — é
assim que a escrita do filho cai na posição certa do array do pai.

## min e max

No `min` o botão de remover some; no `max` o de adicionar some. E o `min`
**semeia** as linhas: a lista nunca fica abaixo dele. Não é só na montagem — num
reset, ou quando o model chega curto de fora, as linhas que faltam entram vazias,
como pelo botão de adicionar. As duas props não viram validação.

E são opcionais quando a `rule` já declara o limite: sem a prop, o `RArray` lê o
limite da própria `rule` — preset ou schema zod (ver [rule](#rule), adiante). A prop
escrita vence, inclusive `:min="0"`.

::demo{src="Array/min-max" title="min e max"}
::

Remover é um `<button>` de verdade, no fim de cada linha: entra no Tab, tem
`aria-label` (o `text.remove`, adiante) e obedece ao `disabled` do campo.

## Reordenar

`sortable` liga duas formas de reordenar, juntas ou uma só:

| valor                           | o que aparece         |
| ------------------------------- | --------------------- |
| `false` (padrão)                | nada                  |
| `true`, ou `sortable` sem valor | as setas **e** a alça |
| `"arrows"`                      | só as setas           |
| `"drag"`                        | só a alça             |

As duas chegam no mesmo lugar:

- **as setas**, um par subir/descer no fim de cada linha. O de subir fica
  desabilitado na primeira, o de descer na última, e o foco **segue o item**:
  depois do clique ele está no mesmo botão da linha para onde o item foi, então dá
  para levar um item do fim ao topo só repetindo Enter. É a forma do teclado;
- **a alça**, no começo de cada linha, para arrastar com mouse ou com o dedo. Uma
  linha indicadora mostra onde o item vai cair, `Escape` cancela no meio do
  caminho, e soltar fora da lista não leva o item para outro `RArray` — o destino
  sai só das linhas desta.

::demo{src="Array/sortable" title="sortable"}
Envie com a segunda linha vazia e depois mova-a, pelas setas ou pela alça: o
erro vai junto.
::

O arraste é por
[Pointer Events](https://developer.mozilla.org/pt-BR/docs/Web/API/Pointer_events),
não pelo drag and drop nativo do HTML, que não dispara em tela de toque. A alça
leva `touch-action: none`, senão o navegador tomaria o gesto para rolar a página.
Ela é `aria-hidden`: quem não usa ponteiro reordena pelas setas — por isso
`"drag"` sozinho deixa a lista sem reordenação pelo teclado.

Para padronizar no app inteiro, `defineFieldDefaults`; a tag continua vencendo —
`:sortable="false"` desliga um campo só, `sortable="arrows"` troca o modo dele.

```ts
// app/rform/defaults.ts
import { defineFieldDefaults } from "#rform/utils";

export default defineFieldDefaults({
    Array: { sortable: "drag" }
});
```

O tipo dos quatro valores é exportado como `Sortable`, do próprio componente:
`import type { Sortable } from "#rform/builtin/fields/Array.vue"`.

### O erro segue o item

O erro de um filho é chaveado pelo caminho com o índice — `convidados.2`,
`socios.1.cpf` (ver [Erros vindos de fora](/pt/form/form#erros-vindos-de-fora)).
Ao remover ou mover uma linha, o `RArray` renumera essas chaves, e a mensagem
continua ao lado do item que a causou. Antes, remover uma linha deixava o erro da
seguinte parado na posição, apontando para outro item.

Quem renumera é `remapIndexKeys`, exportado de `#rform/utils` — útil se você
reordena o model por fora e quer levar um mapa de erros junto. A função devolve o
índice novo, ou `null` para descartar a chave:

```ts
import { remapIndexKeys } from "#rform/utils";

// a linha 1 saiu: a 2 vira 1, e o erro da 1 vai embora
remapIndexKeys(errors, "itens", (i) => (i === 1 ? null : i > 1 ? i - 1 : i));
```

::callout{type="warn"}
Só o **model** e o **erro** seguem o item. Cada linha é presa ao índice — o `id`
de um filho é montado uma vez —, então o estado **local** de um filho fica onde
estava: a fila de upload em voo de um `RFile`, o painel aberto de um `RSelect`.
Mover uma linha no meio de um upload deixa a barra de progresso na posição antiga.
::

## Animação

Adicionar, remover e mover animam pela
[View Transitions API](https://developer.mozilla.org/pt-BR/docs/Web/API/View_Transition_API)
(`document.startViewTransition`). Num browser sem ela, ou com
`prefers-reduced-motion: reduce`, a mudança é aplicada sem animação.

Os `view-transition-name` só existem durante a própria transição — sempre ligados,
eles entrariam também na transição de rota do seu app. O que fica fixo é a
classe: todo elemento animado leva `view-transition-class: rform-array`, e é por
ela que se customiza, no CSS global:

```css
::view-transition-group(*.rform-array) {
    animation-duration: 150ms;
}
```

Para desligar, `animation: none` no mesmo seletor.

::callout{type="warn"}
O `<TransitionGroup>` saiu, e com ele a chave `ui.list.transitionGroup`. Quem a
passava no `ui` ou no `defineFieldDefaults` migra para o CSS acima.
::

## text

`text` é um objeto **aninhado**, espelhando o `defaults.text` do componente —
nunca uma prop achatada tipo `buttonText`. O que você passa entra cru, sem
prefixo: uma chave do seu app ou um `~~` literal.

| chave    | padrão                      | onde aparece                       |
| -------- | --------------------------- | ---------------------------------- |
| `button` | `rform.fields.array.add`    | o rótulo do botão de adicionar     |
| `remove` | `rform.fields.array.remove` | o `aria-label` do botão de remover |
| `up`     | `rform.fields.array.up`     | o `aria-label` do botão de subir   |
| `down`   | `rform.fields.array.down`   | o `aria-label` do botão de descer  |

## rule

::demo{src="Array/rule" title="min e max sobre um array"}
`min` e `max` sobre um array viram `z.array().min()` / `.max()` — de novo, o
schema sai do valor, não do tipo do campo. E os botões seguem esses limites
sozinhos: a lista abre com 2 linhas, a lixeira some com 2, o adicionar com 4, sem
`:min`/`:max`. Sobre um array a mensagem fala de itens: "Mínimo de 2 itens."
::

O limite sai de três formas de `rule`, soltas ou dentro do array de rules:

- o preset por referência — `{ name: "min", min: 2 }`, `{ name: "max", max: 4 }`;
- o [preset `schema`](/pt/concepts/presets#json-schema-o-preset-schema), com o
  JSON Schema vindo do back — `minItems` e `maxItems`;
- um schema [zod](https://zod.dev) — `z.array(...).min(2)`, `.max()`, `.length()`
  (vira mínimo **e** máximo) e `.nonempty()` (mínimo 1), atravessando
  `.optional()`, `.nullable()`, `.default()` e `.transform()`.

Num array que mistura formas vale o limite mais apertado: o maior mínimo e o
menor máximo. Ficam de fora a `rule` em forma de função, que só dá o número
rodando, e o `:rules` agregado do `RForm`, que não chega ao campo.

A direção é uma só, da rule para os botões: a prop `min`/`max` não valida nada.
Quem lê é `ruleLimits`, exportado de `#rform/utils`:

```ts
import { ruleLimits } from "#rform/utils";

ruleLimits([{ name: "min", min: 2 }, z.array(z.string()).max(4)]); // → { min: 2, max: 4 }
```

No modo schema (`RDynamic`, `useRForm`) é igual: a `rule` da config de um campo
`type: "array"` chega ao `RArray`, e os botões seguem o limite nas três formas.

## Uma nota de desempenho

O `v-for` do `RArray` itera `length` e passa cada item por um componente de
linha, em vez de `v-for="(item, index) in model"`. Aquela forma lia **todo**
elemento no render do próprio `RArray`, então uma tecla — uma escrita em
`array[i]` — invalidava a lista inteira e repatchava todo irmão: 0,6 ms com 10
linhas e 4,1 ms com 100, crescendo com a lista onde um formulário plano ficava
plano.

Iterar `length` e passar `item` por um getter não basta sozinho: o `v-bind` num
`<slot>` normaliza o objeto e lê o getter do mesmo jeito. Só a fronteira de
componente escopa a dependência de verdade.

## Ícones

Cada papel é uma chave da prop `icons`, e o valor é o nome do iconify. Os papéis
de um util ficam aninhados sob `Utils`, como no `ui`:
`:icons="{ Utils: { Error: { alert: 'lucide:circle-alert' } } }"`. Camadas,
`defineFieldDefaults` e o alias estão em
[Ícones](/pt/concepts/icones#por-componente-ou-por-tag).

| papel               | padrão                                          | onde aparece                           |
| ------------------- | ----------------------------------------------- | -------------------------------------- |
| `add`               | `rform:plus` → `fa6-solid:plus`                 | no botão de adicionar, abaixo da lista |
| `remove`            | `rform:trash` → `fa6-regular:trash-can`         | no fim de cada linha, para removê-la   |
| `up`                | `rform:chevron-up` → `fa6-solid:chevron-up`     | com `sortable`, para subir a linha     |
| `down`              | `rform:chevron-down` → `fa6-solid:chevron-down` | com `sortable`, para descer a linha    |
| `drag`              | `rform:grip` → `fa6-solid:grip-vertical`        | com `sortable`, a alça de arrastar     |
| `Utils.Error.alert` | `rform:alert` → `ooui:alert`                    | ao lado da mensagem de erro            |

## Camadas de ui

Os botões de cada linha moram em `list.item.actions`. `list.item.move` é a classe
dos dois de mover, e `list.item.remove` a do de remover — os dois são `<button>`,
então `focus-visible:` e `disabled:` valem ali.

O arraste tem quatro chaves: `list.item.handle` é a alça; `list.item.dragging` vai
na linha de origem enquanto ela é arrastada; `list.item.dropBefore` e
`list.item.dropAfter` desenham o indicador, por `before:`/`after:` — é por isso
que `list.item.container` é `relative`. Zerar o `relative` ali solta o indicador
do lugar.
