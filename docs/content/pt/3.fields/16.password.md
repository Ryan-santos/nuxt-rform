`RPassword` é um `RText` de senha com o botão de mostrar e ocultar sempre
presente. O resto é opcional: uma lista de requisitos marcada enquanto se digita,
uma barra de força medida por essa lista e um botão que gera a senha.

## O básico

::demo{src="Password/basico" title="mostrar e ocultar"}
O botão alterna o `type` do input; o model não muda.
::

Passe `autocomplete`: `current-password` numa tela de login, `new-password` num
cadastro ou troca de senha. É o que diz ao gerenciador de senhas se ele deve
preencher a que tem guardada ou oferecer uma nova — veja
[autocomplete](/pt/fields/text#autocomplete).

## checklist

Cada item é `{ label, rule }`. `label` é o texto que se lê (`TrInput`, como todo
texto de campo) e `rule` é **qualquer rule** — um preset, uma função, um schema do
zod, os mesmos formatos do `rule` do campo. A lista é avaliada a cada tecla.

::demo{src="Password/checklist" title="checklist completa, strength e generate"}
Digite devagar e veja cada item marcar. Depois esvazie o campo e rode o submit, e
em seguida preencha só metade dos requisitos e rode de novo.
::

Os quatro estados de um item, no `data-state` do `<li>` e numa chave do
`ui.checklist` cada:

| estado    | quando                                                    |
| --------- | --------------------------------------------------------- |
| `idle`    | campo vazio — vazio é assunto do `required`, não da lista |
| `pending` | o requisito ainda falta                                   |
| `met`     | o requisito foi atendido                                  |
| `failed`  | ainda falta, e um submit já foi reprovado por causa dele  |

**A lista também valida.** Um requisito faltando reprova o `validate()` e o
submit, como qualquer rule do campo. Quem mostra o erro, nesse caso, é a própria
lista, que passa a `failed` — o `RUtilsError` fica calado para não repetir o que
está escrito logo acima. Ele continua falando pelas outras rules do campo, como
o `required` com o campo vazio, e por um `setErrors` do form.

Os requisitos de símbolo, maiúscula e afins saem da rule
[`regex`](/pt/concepts/presets#regex), que existe para isso.

### Uma rule que olha o form

A rule de um item recebe o mesmo `{ value, form }` de qualquer rule, então um
requisito pode depender de outro campo. O que ela devolve só importa por ser
verdadeiro: o texto que aparece é sempre o `label` do item.

## strength

`strength` desenha uma barra com um segmento por requisito, pintada pela fração
de requisitos atendidos:

| atendidos       | nível    |
| --------------- | -------- |
| menos da metade | `weak`   |
| metade ou mais  | `medium` |
| todos           | `strong` |

O nível vai no `data-level` da barra, e as cores são `ui.strength.weak`,
`.medium` e `.strong`. A barra **mede a checklist**: sem `checklist` ela não
renderiza, e o campo avisa no console.

## generate

`generate` liga o botão de gerar. Escutar `@generate` liga também, sem precisar
escrever `generate` ao lado — e `:generate="false"` desliga mesmo com alguém
escutando.

::demo{src="Password/generate" title="@generate e as opções"}
::

O que o botão faz, em ordem:

1. sorteia uma senha com `crypto.getRandomValues` — com pelo menos uma
   minúscula, uma maiúscula, um dígito e, havendo `symbols`, um símbolo;
2. confere contra a `checklist` e sorteia de novo se algum requisito falhar, até
   20 vezes (depois disso avisa no console e fica com a última);
3. escreve no model e mostra a senha, para quem gerou ver o que foi gerado;
4. chama o `@generate` com ela.

Um objeto no lugar de `true` ajusta o sorteio: `length` (16 por padrão) e
`symbols`, o alfabeto de símbolos (`@$!%*?&` por padrão; `""` gera só letras e
dígitos). Um `symbols` que a sua lista recusa nunca passaria nela — é esse o
aviso do passo 2.

O gerador também sai de `#rform/utils`, para usar fora do campo:

```ts
import { generatePassword } from "#rform/utils";

generatePassword({ length: 24, symbols: "#-_" });
```

## Textos

Os textos do campo moram em `rform.fields.password.*` e se trocam pelo `:text`,
como em qualquer campo:

| chave                                   | onde aparece                               |
| --------------------------------------- | ------------------------------------------ |
| `show` / `hide`                         | `title` e `aria-label` do botão de mostrar |
| `generate`                              | `title` e `aria-label` do botão de gerar   |
| `checklist`                             | a mensagem que a lista empurra para o form |
| `strength.weak` / `.medium` / `.strong` | o texto ao lado da barra                   |

## Ícones

Cada papel é uma chave da prop `icons`, e o valor é o nome do iconify. Os papéis
de um util ficam aninhados sob `Utils`, como no `ui`:
`:icons="{ Utils: { Error: { alert: 'lucide:circle-alert' } } }"`. Camadas,
`defineFieldDefaults` e o alias estão em
[Ícones](/pt/concepts/icones#por-componente-ou-por-tag).

| papel                   | padrão                                    | onde aparece                                          |
| ----------------------- | ----------------------------------------- | ----------------------------------------------------- |
| `generate`              | `rform:key` → `fa6-solid:key`             | o botão de gerar senha, com `generate` ou `@generate` |
| `show`                  | `rform:eye` → `fa6-regular:eye`           | o botão de mostrar, com a senha escondida             |
| `hide`                  | `rform:eye-off` → `fa6-regular:eye-slash` | o botão de esconder, com a senha à mostra             |
| `idle`                  | `rform:pending` → `fa6-regular:clock`     | item do `checklist` com o campo vazio                 |
| `pending`               | `rform:pending` → `fa6-regular:clock`     | item do `checklist` ainda não cumprido                |
| `met`                   | `rform:check` → `fa6-solid:check`         | item do `checklist` cumprido                          |
| `failed`                | `rform:remove` → `fa6-solid:xmark`        | item do `checklist` que falhou num submit             |
| `Utils.Loading.loading` | `rform:loading` → `eos-icons:loading`     | o spinner do campo, com a prop `loading`              |
| `Utils.Error.alert`     | `rform:alert` → `ooui:alert`              | ao lado da mensagem de erro                           |
