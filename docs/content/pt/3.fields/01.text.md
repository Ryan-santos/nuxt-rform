`RText` é o campo mais simples do módulo e o que melhor mostra o formato que
todos os outros seguem: um `name` que o liga ao model do formulário, um `label`
e um `placeholder` que passam pelo tradutor, e as duas portas de extensão que
todo campo tem — `mask` para formatar o que se digita e `rule` para validar o
que ficou.

::callout{type="info"}
Este site roda com `@nuxtjs/i18n`, então os demos passam **chave de tradução**
em vez de texto. Num app sem i18n você escreveria `label="Nome"` direto — veja
[Tradução](/pt/concepts/traducao).
::

## O básico

Sem `name`, o campo não entra no model: ele renderiza, aceita digitação e some
do JSON ao lado. É o que se usa para um campo puramente visual.

::demo{src="Text/basico" title="label, placeholder e description"}
O segundo campo não tem `name` — repare que ele não aparece no model.
::

## required

`required` é **marca visual**: acrescenta o asterisco no label e o
`aria-required` no input. Quem valida é a rule `required`, e as duas coisas são
independentes de propósito — um campo pode ser obrigatório na validação sem
gritar isso no label, e vice-versa.

::demo{src="Text/required" title="required e a rule required"}
O primeiro campo só mostra o asterisco. O segundo também recusa o envio vazio.
::

## default

O `default` é semeado pelo `useField` no mount, então já está no model antes de
qualquer digitação — diferente de `modelValue`, que é o valor controlado por
quem monta o formulário.

## loading e error

`loading` mostra o spinner do `RUtilsLoading` no lugar do conteúdo à direita.
`error` injeta a mensagem direto no `RUtilsError`, sem passar por `rule`, e é uma
chave de tradução como o `label`. Para um erro que veio do servidor, o canal é o
[`RForm`](/pt/form/form#erros-vindos-de-fora): ele distribui o mapa inteiro por
`name`, e a mensagem que chega por ali já vem pronta — não passa pelo tradutor de
novo.

::demo{src="Text/loading" title="loading e error"}
::

## autocomplete

`autocomplete` é **prop**, e não atributo de fallthrough. Todo campo tem um
`<div>` na raiz e nenhum declara `inheritAttrs: false`, então um
`autocomplete="username"` escrito na tag pousaria no wrapper — onde o navegador
não o lê, e nenhum gerenciador de senha reconhece o formulário. Sendo prop, ela
desce até o `<input>`.

::demo{src="Text/autocomplete" title="o par de uma tela de login"}
`username` em cima e `current-password` embaixo: é esse par que o preenchedor
procura para saber que a tela é um login. Um dos dois sozinho não diz nada.
::

O valor é `AutocompleteToken`: os tokens do
[WHATWG](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#autofill)
escritos por extenso, mais `(string & {})` — o editor completa `one-time-code` e
`current-password`, e as formas compostas (`"shipping street-address"`,
`"section-a username"`) continuam válidas.

**Seis campos a têm**, e é onde existe controle nativo guardando o valor:

| campo       | onde o atributo pousa     |
| ----------- | ------------------------- |
| `RText`     | o `<input>`               |
| `RTextarea` | o `<textarea>`            |
| `RNumber`   | o `<input type="number">` |
| `RDate`     | o primeiro `<input>`      |
| `RHour`     | o primeiro `<input>`      |
| `RPin`      | o primeiro `<input>`      |

**Nos multi-input é o primeiro, e só ele.** Num `RPin` é onde
`autocomplete="one-time-code"` precisa estar para o Chrome e o Safari oferecerem
o código do SMS — ver [Pin](/pt/fields/pin#autocomplete). Num `RDate` ou num
`RHour` em range, o segundo input não recebe nada: repetir o token ali faria o
preenchedor casar o par errado.

**Ela é lida do merge**, então
[`defineFieldDefaults`](/pt/concepts/ui-e-defaults) padroniza o app inteiro e a
tag continua vencendo:

```ts
// app/rform/defaults.ts
export default defineFieldDefaults({
    Text: { autocomplete: "off" }
});
```

## mask

`mask` aceita três coisas, nesta ordem de resolução: o nome de um preset
embutido, o nome de um preset seu, ou — quando nenhum bate — um pattern cru do
[maska](https://beholdr.github.io/maska/).

Tudo que é do Brasil mora em `br/` e vira `brAlgumaCoisa`.

::demo{src="Text/mask-preset" title="presets embutidos"}
A máscara formata o que fica no model, não só o que aparece na tela.
::

::demo{src="Text/mask-crua" title="pattern cru"}
Nome que não bate com preset nenhum vai direto pro maska.
::

::demo{src="Text/mask-usuario" title="preset do usuário"}
`app/rform/presets/masks/dinheiro.ts` — um arquivo, um preset. Mesmo nome de um
embutido substituiria o embutido.
::

## rule

`rule` aceita nome de preset, `{ name, ...args }`, função, `ZodType` ou um array
de qualquer combinação disso. A validação roda no submit do `RForm`.

::demo{src="Text/rule-nome" title="pelo nome"}
Preset sem argumento obrigatório é referenciado só pelo nome.
::

Os argumentos são **nomeados no próprio ref**, não posicionais:

::demo{src="Text/rule-args" title="com args nomeados"}
`min` escolhe o schema pelo valor — com uma string, vira `z.string().min()`.
::

::demo{src="Text/rule-array" title="em array"}
Roda na ordem; a primeira que falhar é a mensagem que aparece.
::

Uma função recebe **um objeto só**, `{ value, form }`. O `form` é o model
inteiro, provido pelo `RForm` — é por isso que um campo consegue olhar o outro.

::demo{src="Text/rule-fn" title="função e zod"}
::
