`RSelect` aceita `options` em três formatos e decide sozinho o que vira valor e
o que vira rótulo. Compare no painel de model: sem `modelFull` o model guarda só
o valor; com `modelFull` guarda o objeto inteiro.

## options

### Array primitivo

O valor e o rótulo são o próprio item.

::demo{src="Select/primitivo" title="array primitivo"}
::

### Objeto `{ chave: rótulo }`

A chave vira o valor; o valor do objeto vira o rótulo. O que vai pro model é a
chave.

::demo{src="Select/objeto" title="objeto"}
::

### Array de objetos

`pick` diz quais campos do item viram o valor e o rótulo. Ele tem default no
`defaults` do componente (`{ value: "id", label: "name" }`) — e fica **fora** de
`defaults.text` justamente porque não é texto: se estivesse lá dentro, o
auto-prefixo o transformaria em `rform.fields.select.id`, e o Select passaria a
procurar `option["rform.fields.select.id"]`.

O `merger` mescla folha a folha, então `:pick="{ value: 'codigo' }"` conserva o
`label: "name"` do default — sobrescrever uma das duas chaves não apaga a outra.

::demo{src="Select/pick" title="pick"}
::

## multiple

O model vira array. `multiple` é declarado como `Multiple & boolean` — a
interseção é o que força o compilador SFC a emitir `type: Boolean`; sem ela o
atributo sem valor chegaria como string vazia, que é *falsy*.

## search

`search` põe um campo de busca no topo do painel, filtrando as opções pelo
rótulo. É opt-in — numa lista de três itens a busca é ruído.

::demo{src="Select/search" title="busca dentro do painel"}
::

`defineFieldDefaults({ Select: { search: true } })` liga a busca no app inteiro.
Ligada assim, ela **não** se desliga num campo só: a regra "não apaga" do
`merger` pula quando o resultado é truthy e o valor novo é falsy, então o `true`
do app vence o `:search="false"` da tag.

### @search: buscar no servidor

`@search` reporta o termo a cada tecla. Quem escuta **assume o filtro**: o campo
para de filtrar a lista sozinho e passa a mostrar exatamente as `options` que
chegarem. Ele liga o campo de busca sozinho — `search` ao lado é redundante.

::demo{src="Select/busca-remota" title="a lista vem de fora"}
O servidor casa o termo com o nome e com a UF. Digite `BA`.
::

Não é conveniência: filtrar de novo do lado do cliente **esconderia** o que o
servidor casou por um campo que não é o rótulo. Uma cidade da Bahia não tem "BA"
no nome, e um contato achado pelo telefone some da lista enquanto se digita o
telefone.

O debounce fica de fora de propósito — quanto esperar depende da rota que
responde, não do componente que digita. `loading` é a prop de sempre.

::callout{type="warn"}
O que estiver selecionado precisa continuar dentro de `options`. O rótulo do
campo sai do casamento com a lista, então uma busca que não devolva o item já
escolhido deixa o campo em branco com o model intacto. Guarde o selecionado e
concatene-o ao resultado.
::

## Tipagem

O generic de `options` chega até o valor. `modelValue`, `default`, o payload de
`@update:model-value` e o `value`/`label` do slot saem do tipo que você passou —
não há cast a fazer nem `find` na lista para reaver o que o componente já sabia.

```vue
<RSelect
    :options="users"
    :pick="{ value: 'id', label: 'name' }"
    @update:model-value="onlyNumber"
/>
```

Com `users: { id: number, name: string }[]`, o payload é `number`. Com
`model-full`, é o objeto inteiro; com `multiple`, a lista de um ou de outro.

| `options` | `value` | `label` |
|---|---|---|
| array de primitivos | o próprio item | o próprio item |
| array de objetos | `item[pick.value]` | `item[pick.label]` |
| objeto | a chave | o valor, ou `valor[pick.label]` |

`pick.value` e `pick.label` sugerem as chaves do item, mas **não** fecham nelas:
o `getProperty` resolve caminho pontilhado, e `:pick="{ value: 'user.id' }"`
continua válido. Um caminho desses não é `keyof`, então ali o valor volta a ser
`unknown` — que é o que todos os casos eram antes.

::callout{type="warn"}
Escreva o `pick` **inline**. A inferência anda por propriedade, então
`:pick="{ value: 'id' }"` na tag preserva o literal; uma variável de objeto
alarga para `string` e o campo deixa de compilar, reclamando de `"id"` — que é
o default, não a sua chave. A saída é `as const`:

```ts
const pick = { value: "codigo", label: "descricao" } as const;
```
::

## Altura do painel

O painel abre com no máximo `25rem` de altura — o `max-h-100` — e rola por
dentro; numa viewport menor que isso ele encolhe para o espaço livre, virando
para cima quando embaixo não cabe. O teto é a variável `--max-height`, e trocá-lo
é uma arbitrary property no `popover`, por campo ou pelo `defineFieldDefaults`:

```vue
<RSelect
    :options="options"
    :ui="{ Utils: { Dropdown: { popover: '[--max-height:30rem]' } } }"
/>
```

`[--max-height:100vh]` tira o teto e deixa só o ajuste à viewport.
