## Rodar

O gerenciador é o **pnpm**, e o repo é um workspace: um `pnpm install` na raiz
cobre o módulo, o site e os quatro playgrounds.

```bash
pnpm install
pnpm dev:prepare   # popula os .nuxt e os #rform de cada app
```

::callout{type="warn"}
Rodar `pnpm install` **dentro** de um dos subprojetos não instala nada: ele
resolve para a raiz e responde "Already up to date", em 30 ms e com exit 0. Falha
em silêncio.
::

## Os apps

| comando                | o quê                                                     |
| ---------------------- | --------------------------------------------------------- |
| `pnpm run docs`        | este site                                                 |
| `pnpm play`            | playground `i18n` — troca de idioma, packs do usuário     |
| `pnpm play:basic`      | app comum com `@nuxtjs/i18n` — cadastro, `RDynamic`, CRUD |
| `pnpm play:standalone` | **sem** `@nuxtjs/i18n` — o motor de tradução próprio      |
| `pnpm play:ui`         | tokens `--rf-*`, `defineFieldDefaults`, `ui` por campo    |

Cada playground prova um eixo diferente em condições de app real. O
`standalone` é o único lugar onde o motor próprio roda, e o `ui` é o único onde
o tema é sobrescrito.

## Testes

```bash
pnpm test          # vitest: unit + nuxt + e2e
pnpm test:types    # vue-tsc nos sete apps, mais o server/ do site
pnpm lint          # oxlint
```

O `test:types` roda **oito** `vue-tsc`: o módulo, a fixture, o site, os quatro
playgrounds e o `server/` do site, onde moram as ferramentas do
[MCP](/pt/support/mcp) — nenhum `tsconfig.app.json` as inclui. Cada app Nuxt tem
o próprio `.nuxt` e o próprio `#rform`, então checar um não cobre outro.

## Convenções

- 4 espaços, aspas duplas, ponto e vírgula, `trailingComma: "none"`,
  `singleAttributePerLine: true`. É o `oxfmt.config.ts`.
- Comentário e JSDoc em **pt-BR**; código em inglês (nome de variável, tipo,
  chave de `ui`, mensagem de `throw`).
- Comentário curto, e só no que não é óbvio. O racional longo mora no
  `.claude/CLAUDE.md`.

## Cuidado com o teste de tema

`test/unit/theme.test.ts` tokeniza o arquivo `.vue` **inteiro**, comentário
incluído. Uma classe Tailwind literal (`rounded-xl`, `bg-primary`) ou um
`(--rf-…)` dentro de um comentário **quebra o teste**. Exemplo em componente
mostra a tag, nunca a classe.

## Documentação

Uma página aqui é um `.md` em `docs/content/{pt,en}/`, e as duas árvores são
espelho arquivo a arquivo — `test/unit/docs.test.ts` cobra a paridade.

Um demo é um `.vue` de verdade em `docs/app/demos/<Componente>/<id>.vue`,
referenciado por `::demo{src="Componente/id"}`. Ele passa por `vue-tsc` como
qualquer outro arquivo — e o teste também confere que todo `src` citado no
conteúdo aponta para um arquivo que existe.

Duas coisas aqui são **geradas** do fonte: a tabela de props e o JSON que as
ferramentas do [MCP](/pt/support/mcp) leem. Dois módulos Nuxt em `docs/modules/`
escrevem os dois em todo `dev`, `build` e `prepare`, então eles sempre batem com o
fonte.
