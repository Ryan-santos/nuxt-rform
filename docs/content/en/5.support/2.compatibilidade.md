## What changes with `@nuxtjs/i18n`

Installing it swaps the translation engine **at build time**, with no
configuration:

|             | without `@nuxtjs/i18n`        | with                                       |
| ----------- | ----------------------------- | ------------------------------------------ |
| engine      | its own `@intlify/core`       | a bridge to the app's `$i18n`              |
| bundle cost | ~137 kB                       | **zero**                                   |
| `TrInput`   | `string`                      | a narrow union generated from your `.json` |
| `~~Name`    | prints `~~Name`               | prints `Name`                              |
| user pack   | `app/rform/locales/<code>.ts` | the `rform` key in the app's locale        |

The detection is `hasNuxtModule("@nuxtjs/i18n")`, which reads the **declared**
module list — so it does not depend on rform being registered before or after
i18n.

## What changes with Tailwind

Without Tailwind, nothing emits the module's classes. Use
`css: ["nuxt-rform/style.css"]`, the already-built CSS the package exports.

## SSR

Supported. Every field renders on the server.

Three details worth noting:

- This site's code blocks use `data-allow-mismatch`, because the highlighting is
  generated from a string.
- `RUtilsDropdown` positions on the client (it is layout), so the panel only
  measures after hydration.
- The theme switcher also uses `data-allow-mismatch`: its value comes from
  `localStorage`, which the server does not have.

## Accessibility

What is already there: `aria-required` coming from `required`, a real `label`
associated with the input, `role="radiogroup"` on the option pickers, keyboard
navigation in `RPin` and `RSelect`.

## Browsers

Nuxt 4's default targets. The CSS uses `color-mix()`, `light-dark()` and
`:has()` — all widely supported since 2023/2024. The autofill reset relies on
`:-webkit-autofill`, which Chrome, Safari and Firefox 86+ implement.
