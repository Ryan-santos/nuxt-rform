## Why does `required` not validate?

Because the two things are deliberately independent. `required` is the **visual
mark** — the asterisk on the label and `aria-required` on the input. A field can
be required by validation without shouting about it in the label, and can shout
without being (on a draft form, say). To validate, add `rule="required"`.

## My field is missing from the model

It has no `name`. Without `name`, `useField` does not write into the parent's
model — the field renders and works, but stays out. That is what a purely visual
field relies on.

## Why does `safeParse` throw?

Because a `rule` referenced by preset name becomes `z.any().superRefine(async …)`
in the aggregated `rules`, and zod refuses a synchronous parse over an async
refinement. Use `safeParseAsync`. A schema made **only** of `ZodType` stays
synchronous.

## The module's classes do not show up

The CSS line is missing. Tailwind does not scan `node_modules`, so without the
`@source` that `#rform/tailwindcss` brings, no class of the module is emitted:

```css
@import "tailwindcss";
@import "#rform/tailwindcss";
```

And it has to be an `@import` from your Tailwind **entry**, never
`nuxt.options.css`: in a file Tailwind does not treat as part of an entry,
`@source` is ignored and the at-rule leaks raw to the browser.

## My fields are transparent

Same cause as above, or a `--rf-*` override declared **outside** `@layer rform`
with `#rform` imported last. See the table in
[Theme](/en/concepts/tema#how-to-override).

## `label="Name"` does not compile

Your app has `@nuxtjs/i18n` with a readable `.json`, so `TrInput` narrowed to
"a key of your app, a key of the module, or a marked literal". Write
`label="form.name"` or `label="~~Name"`. It is the behavior documented in
[Translation](/en/concepts/traducao#trinput-the-type-is-generated-from-your-message-file).

## `~~Name` is printing the tildes

Your app does **not** have `@nuxtjs/i18n`. Without the bridge there is nothing to
resolve an app key against, so `tr` is the identity and the marker survives. It
is an accepted cost, not a bug — see the `~~` asymmetry in
[Translation](/en/concepts/traducao).

## `TS2614: Module '#rform/utils' has no exported member 'defineRule'`

The barrel emits its specifiers without an extension precisely so your app does
not need `allowImportingTsExtensions`. If you are seeing this, you most likely
have not run `nuxi prepare` — the template has not been generated yet.

## A prop my util declares does not exist on the field

Almost always your app's missing `tsconfig.json`. `ts.findConfigFile` walks up
from the file; with no tsconfig at the app's root it finds one from a project
above, and `@vue/compiler-sfc` resolves `#rform/types/...` against **that**
project's generated types. The symptom is exactly this one, and it is silent: the
prop lands as a fallthrough attribute, with no compile error.

## An `@` in my message takes the page down

`@:key` is vue-i18n's linked-message syntax, and it does not ask for opt-in.
Write `{'@'}`:

```json
{ "emailExample": "you{'@'}company.com" }
```

The runtime error is `Invalid linked format (error code: 10)`, naming the message
path — not the `@`, so the symptom does not point at the problem.

## Do I really need zod?

Yes. `zod` is a **required** peer dependency: the built-in rules are zod schemas,
and `#rform/presets` imports all of them statically. What the module does is keep
zod off the critical path — `#rform/presets` is only ever reached through a dynamic
import, and only when a field declares a `rule`.

A `mask` does not go through there: masks live in `#rform/masks`, which is imported
statically and knows nothing about zod.

## Can I use it without Tailwind?

The components work, but nobody emits their classes. For that case the package
exports the already-built CSS:

```ts
css: ["nuxt-rform/style.css"];
```
