## Install

```bash
pnpm add nuxt-rform zod
```

`zod` is a **required** peer dependency: the built-in rules are zod schemas, and
`#rform/presets` imports all of them statically. That barrel is only ever reached
through a dynamic import, so zod stays off the critical path of a page with no
validation.

## Register the module

```ts
export default defineNuxtConfig({
    modules: ["nuxt-rform"]
});
```

::callout
The npm package is **`nuxt-rform`** — the `nuxt-` prefix is the ecosystem
convention, and it is what makes the module discoverable. Everything else stays
short: the config key is `rform`, the alias is `#rform`, and your own files
live in `app/rform/`.
::

rform declares `@nuxt/icon` as a module dependency and already registers the 16
icon aliases it uses, all under the `rform:` namespace — `rform:plus`,
`rform:remove`, `rform:loading`, `rform:calendar`… There is nothing to configure
there, and swapping one of them is [overriding the alias](/en/concepts/tema#the-icons).

## The CSS

One line in your Tailwind entry, and it brings both things: the `@source` for
the module's components (Tailwind does not scan `node_modules`, so without it no
class of the module is emitted) and the theme tokens.

```css
@import "tailwindcss";
@import "#rform/tailwindcss";
```

::callout{type="warn"}
Put `#rform/tailwindcss` **after** `tailwindcss`, as above. The order only
matters when both declare the same variable, but in that order all five override
forms work — including an app `@theme`. Details in [Theme](/en/concepts/tema).
::

It has to be an `@import` from your entry, never `nuxt.options.css`: in a file
Tailwind does not treat as part of an entry, `@source` is ignored and the at-rule
leaks raw to the browser.

### Without Tailwind

An app without Tailwind gets no tokens that way. For that case the package
exports the built CSS:

```ts
export default defineNuxtConfig({
    modules: ["nuxt-rform"],
    css: ["nuxt-rform/style.css"]
});
```

## Module options

```ts
export default defineNuxtConfig({
    modules: ["nuxt-rform"],

    rform: {
        // Language used when the app does NOT have @nuxtjs/i18n.
        // With it installed, its locale wins — this value is not read.
        locale: "pt-BR"
    }
});
```

## Your app's tsconfig

A Nuxt app with no `tsconfig.json` at its root ends up finding the tsconfig of a
project above it — and `@vue/compiler-sfc` resolves `#rform/types/...` against
**that** project's generated types. The symptom is silent: the props a util
contributes are simply not declared, and `<RRating hint="…">` lands as a
fallthrough attribute with no compile error.
