`RPassword` is a password `RText` with the show/hide button always there. The
rest is optional: a list of requirements checked as you type, a strength bar
measured by that list, and a button that generates the password.

## The basics

::demo{src="Password/basico" title="show and hide"}
The button toggles the input's `type`; the model does not change.
::

Pass `autocomplete`: `current-password` on a login screen, `new-password` on a
sign-up or password change. It is what tells the password manager whether to
fill in the one it has stored or offer a new one — see
[autocomplete](/en/fields/text#autocomplete).

## checklist

Each item is `{ label, rule }`. `label` is the text that is read (`TrInput`, like
every field text) and `rule` is **any rule** — a preset, a function, a zod
schema, the same shapes as the field's own `rule`. The list is evaluated on every
keystroke.

::demo{src="Password/checklist" title="full checklist, strength and generate"}
Type slowly and watch each item check. Then empty the field and hit submit, and
after that fill in only half the requirements and hit it again.
::

An item's four states, in the `<li>`'s `data-state` and one `ui.checklist` key
each:

| state     | when                                                           |
| --------- | -------------------------------------------------------------- |
| `idle`    | the field is empty — empty belongs to `required`, not the list |
| `pending` | the requirement is still missing                               |
| `met`     | the requirement is met                                         |
| `failed`  | still missing, and a submit has already failed because of it   |

**The list also validates.** A missing requirement fails `validate()` and the
submit, like any of the field's rules. The one showing the error, in that case,
is the list itself, which switches to `failed` — `RUtilsError` stays quiet so it
does not repeat what is written right above it. It still speaks for the field's
other rules, like `required` with the field empty, and for a form `setErrors`.

The symbol, uppercase and similar requirements come from the
[`regex`](/en/concepts/presets#regex) rule, which exists for this.

### A rule that looks at the form

An item's rule receives the same `{ value, form }` as any rule, so a requirement
can depend on another field. What it returns only matters for being truthy: the
text shown is always the item's `label`.

::

## strength

`strength` draws a bar with one segment per requirement, painted by the fraction
of requirements met:

| met            | level    |
| -------------- | -------- |
| less than half | `weak`   |
| half or more   | `medium` |
| all            | `strong` |

The level goes in the bar's `data-level`, and the colors are
`ui.strength.weak`, `.medium` and `.strong`. The bar **measures the checklist**:
without a `checklist` it does not render, and the field warns in the console.

## generate

`generate` turns on the generate button. Listening to `@generate` turns it on
too, with no `generate` needed next to it — and `:generate="false"` turns it off
even with someone listening.

::demo{src="Password/generate" title="@generate and the options"}
::

What the button does, in order:

1. draws a password with `crypto.getRandomValues` — with at least one lowercase,
   one uppercase, one digit and, when there are `symbols`, one symbol;
2. checks it against the `checklist` and draws again if any requirement fails,
   up to 20 times (after that it warns in the console and keeps the last one);
3. writes it to the model and reveals it, so whoever generated it sees what was
   generated;
4. calls `@generate` with it.

An object instead of `true` tunes the draw: `length` (16 by default) and
`symbols`, the symbol alphabet (`@$!%*?&` by default; `""` generates letters and
digits only). A `symbols` your list rejects would never pass it — that is the
warning in step 2.

The generator also comes out of `#rform/utils`, for use outside the field:

```ts
import { generatePassword } from "#rform/utils";

generatePassword({ length: 24, symbols: "#-_" });
```

## Texts

The field's texts live under `rform.fields.password.*` and are swapped through
`:text`, as in any field:

| key                                     | where it shows                                 |
| --------------------------------------- | ---------------------------------------------- |
| `show` / `hide`                         | the show button's `title` and `aria-label`     |
| `generate`                              | the generate button's `title` and `aria-label` |
| `checklist`                             | the message the list pushes to the form        |
| `strength.weak` / `.medium` / `.strong` | the text next to the bar                       |
