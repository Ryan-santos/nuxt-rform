`RSelect` accepts `options` in three shapes and works out on its own what
becomes the value and what becomes the label. Compare in the model panel:
without `modelFull` the model keeps only the value; with `modelFull` it keeps
the whole object.

## options

### Primitive array

The value and the label are the item itself.

::demo{src="Select/primitivo" title="primitive array"}
::

### Object `{ key: label }`

The key becomes the value; the object's value becomes the label. What reaches
the model is the key.

::demo{src="Select/objeto" title="object"}
::

### Array of objects

`pick` says which fields of the item become the value and the label. It has a
default in the component's `defaults` (`{ value: "id", label: "name" }`) — and it
lives **outside** `defaults.text` precisely because it is not text: were it in
there, the auto-prefix would turn it into `rform.fields.select.id`, and Select
would start looking up `option["rform.fields.select.id"]`.

The `merger` merges leaf by leaf, so `:pick="{ value: 'code' }"` keeps the
default's `label: "name"` — overriding one of the two keys does not erase the
other.

::demo{src="Select/pick" title="pick"}
::

## multiple

The model becomes an array. `multiple` is declared as `Multiple & boolean` — the

the valueless attribute would arrive as an empty string, which is falsy.

## search

`search` puts a search box at the top of the panel, filtering the options by
label. It is opt-in — on a three-item list the search is noise.

::demo{src="Select/search" title="search inside the panel"}
::

`defineFieldDefaults({ Select: { search: true } })` turns the search on app-wide.
Turned on that way, it **cannot** be turned off on a single field: the merger's
"never erases" rule skips when the result is truthy and the new value is falsy,
so the app's `true` beats a `:search="false"` on the tag.

### @search: searching on the server

`@search` reports the term on every keystroke. Whoever listens **takes over the
filter**: the field stops filtering the list on its own and shows exactly the
`options` it is given. It turns the search box on by itself — `search` next to
it is redundant.

::demo{src="Select/busca-remota" title="the list comes from outside"}
The server matches the term against the name and the state. Type `BA`.
::

This is not a convenience: filtering again on the client would **hide** what the
server matched on a field that is not the label. A city in Bahia has no "BA" in
its name, and a contact found by phone number disappears from the list while you
type the phone number.

The debounce is deliberately left out — how long to wait depends on the route
answering, not on the component doing the typing. `loading` is the usual prop.

::callout{type="warn"}
Whatever is selected has to stay inside `options`. The field's label comes from
matching against the list, so a search that does not return the already-chosen
item leaves the field blank with the model untouched. Keep the selected one and
concatenate it onto the result.
::

## Typing

The generic of `options` reaches the value. `modelValue`, `default`, the
`@update:model-value` payload and the slot's `value`/`label` all come from the
type you passed — no cast to write, no `find` over the list to win back what
the component already knew.

```vue
<RSelect
    :options="users"
    :pick="{ value: 'id', label: 'name' }"
    @update:model-value="onlyNumber"
/>
```

With `users: { id: number, name: string }[]`, the payload is `number`. With
`model-full`, the whole object; with `multiple`, a list of either.

| `options` | `value` | `label` |
|---|---|---|
| array of primitives | the item itself | the item itself |
| array of objects | `item[pick.value]` | `item[pick.label]` |
| object | the key | the value, or `value[pick.label]` |

`pick.value` and `pick.label` suggest the item's keys, but do **not** close over
them: `getProperty` resolves a dotted path, and `:pick="{ value: 'user.id' }"`
stays valid. Such a path is not a `keyof`, so the value falls back to `unknown`
there — which is what every case used to be.

::callout{type="warn"}
Write `pick` **inline**. Inference walks per property, so `:pick="{ value: 'id' }"`
on the tag keeps the literal; an object variable widens to `string` and the
field stops compiling, complaining about `"id"` — which is the default, not your
key. The way out is `as const`:

```ts
const pick = { value: "code", label: "description" } as const;
```
::

## Panel height

The panel opens at most `25rem` tall — the `max-h-100` — and scrolls inside;
in a shorter viewport it shrinks to the free space, flipping upward when it
does not fit below. The cap is the `--max-height` variable, and changing it is
an arbitrary property on the `popover`, per field or through
`defineFieldDefaults`:

```vue
<RSelect
    :options="options"
    :ui="{ Utils: { Dropdown: { popover: '[--max-height:30rem]' } } }"
/>
```

`[--max-height:100vh]` removes the cap and leaves only the viewport fit.
