`RSelect` accepts `options` in three shapes and works out on its own what
becomes the value and what becomes the label. Compare in the model panel:
without `modelFull` the model keeps only the value; with `modelFull` it keeps
the whole object.

## options

### Primitive array

The value and the label are the item itself.

::demo{src="Select/primitivo" title="primitive array"}
::

### Object `{ key: label }`

The key becomes the value; the object's value becomes the label. What reaches
the model is the key.

::demo{src="Select/objeto" title="object"}
::

### Array of objects

`pick` says which fields of the item become the value and the label. It has a
default in the component's `defaults` (`{ value: "id", label: "name" }`) — and it
lives **outside** `defaults.text` precisely because it is not text: were it in
there, the auto-prefix would turn it into `rform.fields.select.id`, and Select
would start looking up `option["rform.fields.select.id"]`.

The `merger` merges leaf by leaf, so `:pick="{ value: 'code' }"` keeps the
default's `label: "name"` — overriding one of the two keys does not erase the
other.

::demo{src="Select/pick" title="pick"}

## search

`search` puts a search box at the top of the panel, filtering the options by
label. It is opt-in — on a three-item list the search is noise.

::demo{src="Select/search" title="search inside the panel"}
::

`defineFieldDefaults({ Select: { search: true } })` turns the search on app-wide.
Turned on that way, it **cannot** be turned off on a single field: the merger's
"never erases" rule skips when the result is truthy and the new value is falsy,
so the app's `true` beats a `:search="false"` on the tag.

### @search: searching on the server

`@search` reports the term on every keystroke. Whoever listens **takes over the
filter**: the field stops filtering the list on its own and shows exactly the
`options` it is given. It turns the search box on by itself — `search` next to
it is redundant.

::demo{src="Select/busca-remota" title="the list comes from outside"}
The server matches the term against the name and the state. Type `BA`.
::

This is not a convenience: filtering again on the client would **hide** what the
server matched on a field that is not the label. A city in Bahia has no "BA" in
its name, and a contact found by phone number disappears from the list while you
type the phone number.

The debounce is deliberately left out — how long to wait depends on the route
answering, not on the component doing the typing. `loading` is the usual prop.

`@search` is a **report**: it reports the term and nothing else. When the field
itself should search and paginate, what you pass is a function in `options` — the
next section.

## options as a function

`options` also takes a function. Then the app does the searching, and the module
owns the **cycle**: debounce, page number, end of the list, error with retry, and
the label of whatever is already chosen.

```ts
const search = ({ search, page, signal }) =>
    $fetch("/api/users", { query: { search, page }, signal });
```

::demo{src="Select/remoto" title="loads as you scroll"}
500 names, 20 per page. Scroll to the end of the list for the next one.
::

The context the function receives:

| key | what |
|---|---|
| `search` | the typed term, with the debounce already applied |
| `page` | **1-based**. Page 1 is the first `open`, and every scroll to the end asks for the next |
| `loaded` | what is already in the list, for paginating by last item instead |
| `value` | the field's model |
| `form` | the whole `RForm` model |
| `signal` | an `AbortSignal` — the stale request is aborted |

**An empty array ends it.** There is no envelope to build and no cursor to return:
the function returns the page, and an empty page says it is over. A page that
does not grow the list ends it too — that is the guard against a function that
ignores `page` and always returns the same thing, whose symptom would be the
browser freezing.

The debounce is the `debounce` prop, in milliseconds, defaulting to `300`. `0`
turns it off.

**It does not turn the search box on by itself**, unlike `@search`: an infinite
list with no term at all is legitimate use, and turning the box on there would be
a surprise. Write `search` when you want both.

With `options` as a function the local filter **gives up** — the list that came
back is already the answer to the term. Same reason as `@search`, same motive.

### The chosen one's label does not leave the screen

This is the difference that matters against `@search`. The field keeps the label
of what was chosen, so typing in the search box, paginating and reopening the
panel do not erase the name in the field — and there is no need to concatenate
the selected item onto the result the way `@search` requires.

The cache holds only what was **chosen or resolved**, never the list: it is
bounded by the number of selections, not by the number of searches.

### The selected section

In remote mode whatever is chosen rises into a fixed block at the top of the
panel, outside the scrolling list. The point is not to lose sight of the
selection **while paginating** — at the top of the list it would scroll away on
the first drag, which is exactly when it is useful.

The search does not filter it, and the row is the same row: same slot, same
click, and under `multiple` clicking deselects. With `multiple` and many
selections it stops growing and scrolls inside; the height is the `ui.list.pinned`
key, which is what an app with wide selection will want to change:

```vue
<RSelect
    :options="search"
    multiple
    :ui="{ list: { pinned: 'max-h-72' } }"
/>
```

In static mode the section does not exist: there the chosen one is already in the
list and always was, and lifting it would reorder the list for people who never
asked for any of this.

### States

Loading, empty and error each have their own place. The first page takes the
list's place; the next one, a strip in the footer. Failing to load is **not** a
validation failure — it never becomes the field's `error`, which has a single
writer.

The two new slots are `empty`, in the list's place, and `footer`, in the strip
below it — the latter receives `status` and `retry`, because a network error with
no button is a dead end.

## resolve

On an edit screen the model already arrives filled in, and its value may not be
on the first page. `resolve` translates the value into the item:

```ts
const resolve = ({ value, signal }) =>
    $fetch(`/api/users/${value}`, { signal }).then((user) => [user]);
```

::demo{src="Select/resolve" title="opens already filled"}
The `default` is id 317, which is not on the first page.
::

It runs once per unknown key — including when the model changes from outside, on
a form reset or a CRUD's `load(id)` — and what it returns feeds **only** the label
cache, never the list: a resolved item showing up in the panel would be a
duplicate.

It does **not** run with static `options` (there "not in the list" means "does not
exist"), nor with an empty model, nor for a key the page or the cache already
answer — so choosing through the UI never fires a request.

::callout
**With `modelFull` you do not need `resolve`.** The model is already the whole
object, and the label comes out of it through `pick.label` — no cache, no request
and no flash of the raw value. It is the cheap route for an edit screen.
::

Like any function prop, `resolve` takes `false` to refuse what a
`defineFieldDefaults` standardized for the whole app.

## Long lists

Above 100 rows the panel renders only the visible window. It turns on by itself —
there is no prop to write:

::demo{src="Select/virtual" title="5,000 options"}
Open the inspector: the panel has ~20 children, not 5,000.
::

`@tanstack/vue-virtual` travels in a separate chunk, loaded only when the list
crosses the threshold — an app that never renders 20 options does not pay for it
in the bundle.

The switch is monotonic within one opening: once virtualized the list stays that
way until the panel closes, because alternating strategy on every keystroke is
scroll and focus jitter.

`rowHeight` (default `48`) is a row's estimated height, and only governs the
scrollbar before the first measurement — rows are really measured after the first
render, which is what makes the free slot work.

## Typing

The generic of `options` reaches the value. `modelValue`, `default`, the
`@update:model-value` payload and the slot's `value`/`label` all come from the
type you passed — no cast to write, no `find` over the list to win back what
the component already knew.

```vue
<RSelect
    :options="users"
    :pick="{ value: 'id', label: 'name' }"
    @update:model-value="onlyNumber"
/>
```

With `users: { id: number, name: string }[]`, the payload is `number`. With
`model-full`, the whole object; with `multiple`, a list of either.

| `options` | `value` | `label` |
|---|---|---|
| array of primitives | the item itself | the item itself |
| array of objects | `item[pick.value]` | `item[pick.label]` |
| object | the key | the value, or `value[pick.label]` |

`pick.value` and `pick.label` suggest the item's keys, but do **not** close over
them: `getProperty` resolves a dotted path, and `:pick="{ value: 'user.id' }"`
stays valid. Such a path is not a `keyof`, so the value falls back to `unknown`
there — which is what every case used to be.

::callout{type="warn"}
Write `pick` **inline**. Inference walks per property, so `:pick="{ value: 'id' }"`
on the tag keeps the literal; an object variable widens to `string` and the
field stops compiling, complaining about `"id"` — which is the default, not your
key. The way out is `as const`:

```ts
const pick = { value: "code", label: "description" } as const;
```
::

## Panel height

The panel opens at most `25rem` tall — the `max-h-100` — and scrolls inside;
in a shorter viewport it shrinks to the free space, flipping upward when it
does not fit below. The cap is the `--max-height` variable, and changing it is
an arbitrary property on the `popover`, per field or through
`defineFieldDefaults`:

```vue
<RSelect
    :options="options"
    :ui="{ Utils: { Dropdown: { popover: '[--max-height:30rem]' } } }"
/>
```

`[--max-height:100vh]` removes the cap and leaves only the viewport fit.
