`RCheckbox` has two modes, and the presence of `options` decides which:

| `options` | the model                    | the text next to it         |
| --------- | ---------------------------- | --------------------------- |
| absent    | `boolean`                    | `placeholder`, as in Switch |
| present   | the list of checked `value`s | each option's label         |

## Boolean

Without `options`, `placeholder` is the text on the same line as the box — the
same role it has in [Switch](/en/fields/switch). `label` sits above, as in the
other fields.

::demo{src="Checkbox/booleano" title="placeholder beside, label above"}
::

## options

With `options`, each option is a box, and the model holds the checked values in
the order they were checked. The three formats and `pick` are the same as in
[Select](/en/fields/select#options).

The model starts as `[]` without touching the field: the boolean mode's
`false` never reaches the form.

::demo{src="Checkbox/options" title="list"}
::

### Array of objects and slot

`pick` chooses the value and the label. The default slot receives
`{ option, checked }`, with `option.original` being the raw item, and replaces
each box's label.

::demo{src="Checkbox/pick" title="pick and slot"}
::

## States

The `required` rule treats an unchecked box (`false`) and an empty list (`[]`)
as empty, so it serves both modes.

::demo{src="Checkbox/estados" title="required in both modes, disabled and error"}
::
