`RText` is the simplest field in the module and the one that best shows the
shape every other field follows: a `name` that binds it to the form model, a
`label` and a `placeholder` that go through the translator, and the two
extension points every field has — `mask` to format what gets typed and `rule`
to validate what is left.

::callout{type="info"}
This site runs with `@nuxtjs/i18n`, so the demos pass a **translation key**
instead of text. In an app without i18n you would write `label="Name"` directly
— see [Translation](/en/concepts/traducao).
::

## The basics

Without a `name`, the field never reaches the model: it renders, it accepts
typing, and it is absent from the JSON beside it. That is what a purely visual
field looks like.

::demo{src="Text/basico" title="label, placeholder and description"}
The second field has no `name` — notice it does not show up in the model.
::

## required

`required` is a **visual mark**: it adds the asterisk to the label and
`aria-required` to the input. Validation is the `required` rule's job, and the
two are deliberately independent — a field can be required by validation
without shouting about it in the label, and the other way around.

::demo{src="Text/required" title="required and the required rule"}
The first field only shows the asterisk. The second also refuses an empty
submit.
::

## loading and error

`loading` shows the `RUtilsLoading` spinner in place of the trailing content.
`error` injects the message straight into `RUtilsError`, bypassing `rule`, and it
is a translation key just like `label`. For an error that came back from the
server the channel is the [`RForm`](/en/form/form#errors-from-the-outside): it
spreads the whole map by `name`, and a message arriving that way is already
resolved — it does not go through the translator again.

::demo{src="Text/loading" title="loading and error"}
::

## autocomplete

`autocomplete` is a **prop**, not a fallthrough attribute. Every field has a
`<div>` at its root and none of them declares `inheritAttrs: false`, so an
`autocomplete="username"` written on the tag would land on the wrapper — where
the browser never reads it, and no password manager recognises the form. As a
prop, it reaches the `<input>`.

::demo{src="Text/autocomplete" title="the pair of a login screen"}
`username` on top and `current-password` below: that pair is what the autofiller
looks for to know the screen is a login. Either one alone says nothing.
::

The value is `AutocompleteToken`: the
[WHATWG](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#autofill)
tokens spelled out, plus `(string & {})` — your editor completes `one-time-code`
and `current-password`, and the composed forms (`"shipping street-address"`,
`"section-a username"`) stay valid.

**Six fields have it**, which is wherever a native control holds the value:

| field       | where the attribute lands   |
| ----------- | --------------------------- |
| `RText`     | the `<input>`               |
| `RTextarea` | the `<textarea>`            |
| `RNumber`   | the `<input type="number">` |
| `RDate`     | the first `<input>`         |
| `RHour`     | the first `<input>`         |
| `RPin`      | the first `<input>`         |

**On multi-input fields it is the first one, and only it.** In an `RPin` that is
where `autocomplete="one-time-code"` has to be for Chrome and Safari to offer the
SMS code — see [Pin](/en/fields/pin#autocomplete). In an `RDate` or an `RHour` in
range mode the second input gets nothing: repeating the token there would make
the autofiller match the wrong pair.

**It is read from the merge**, so
[`defineFieldDefaults`](/en/concepts/ui-e-defaults) standardises the whole app
and the tag still wins:

```ts
// app/rform/defaults.ts
export default defineFieldDefaults({
    Text: { autocomplete: "off" }
});
```

## mask

`mask` accepts three things, resolved in this order: the name of a built-in
preset, the name of one of your own presets, or — when neither matches — a raw
[maska](https://beholdr.github.io/maska/) pattern.

Everything Brazil-specific lives under `br/` and becomes `brSomething`.

::demo{src="Text/mask-preset" title="built-in presets"}
The mask formats what lands in the model, not just what shows on screen.
::

::demo{src="Text/mask-crua" title="raw pattern"}
A name that matches no preset goes straight to maska.
::

::demo{src="Text/mask-usuario" title="your own preset"}
`app/rform/presets/masks/dinheiro.ts` — one file, one preset. The same name as a
built-in would replace the built-in.
::

## rule

`rule` accepts a preset name, `{ name, ...args }`, a function, a `ZodType`, or
an array of any combination of those. Validation runs on the `RForm` submit.

::demo{src="Text/rule-nome" title="by name"}
A preset with no required argument is referenced by name alone.
::

Arguments are **named in the ref itself**, not positional:

::demo{src="Text/rule-args" title="with named args"}
`min` picks the schema from the value — with a string, it becomes
`z.string().min()`.
::

::demo{src="Text/rule-array" title="as an array"}
They run in order; the first one that fails is the message that shows.
::

A function receives **a single object**, `{ value, form }`. `form` is the whole
model, provided by `RForm` — that is how one field gets to look at another.

::demo{src="Text/rule-fn" title="function and zod"}
::
