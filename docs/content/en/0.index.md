`rform` is a Nuxt forms module. It ships thirteen ready-made fields (`RText`,
`RSelect`, `RDate`, `RArray`…), an `RForm` that binds all of them to a single
model, and a `useRForm` that decides where the types and the validation come
from.

```vue
<template>
    <RForm v-model="data">
        <RText
            name="name"
            label="Name"
            required
            rule="required"
        />
        <RText
            name="cpf"
            label="CPF"
            mask="brCpf"
            rule="brCpf"
        />
    </RForm>
</template>

<script setup lang="ts">
    const { data } = useRForm<{ name?: string; cpf?: string }>();
</script>
```

## Why it exists

A real form has four things that usually live in four different places: the
**UI**, the **model**, the **types** and the **validation**. When they drift
apart, every new field is four edits — and the one you forget will not tell you.

Here they meet at the field. `name` binds the field to the model. `rule` binds
the field to the validation. `mask` binds the field to the format. And the type
of `modelValue` comes out of the `default` the component itself declares.

## What it does not do

- **It is not a design system.** Every class in the module is overridable by
  named layer, and every color goes through a `--rf-*` variable. Changing the
  theme is changing a variable.
- **It does not invent a validation language.** `rule` takes zod directly; the
  built-in presets _are_ zod.
- **It hardcodes no text.** No message in the module is a literal — and in an app
  with `@nuxtjs/i18n` the module itself speaks through the app's store.
