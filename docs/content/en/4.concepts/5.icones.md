rform declares `@nuxt/icon` as a module dependency and draws every icon through an
**alias** under the `rform:` namespace. Color and radius are a variable
([Theme](/en/concepts/tema)); an icon is an alias.

## The base

The 20 aliases the module registers, with the iconify icon each one points to. The
table is read from the `@nuxt/icon` config at runtime, so it is always the real list:

::icons-table
::

`rform:image` is offered to the app without any of the module's components using it.

## Swapping for the whole app

**Swapping an icon for the whole app is overriding the alias**, in `nuxt.config`
(for one component or one tag it is the [`icons`](#per-component-or-per-tag) prop,
below):

```ts
export default defineNuxtConfig({
    modules: ["nuxt-rform"],
    icon: {
        aliases: {
            "rform:calendar": "lucide:calendar",
            "rform:remove": "lucide:trash-2"
        }
    }
});
```

::callout{type="tip"}
Overriding one alias **does not take the other 19 down**: the Nuxt merge is deep,
key by key, and your value wins only on the key you wrote. Write one, the nineteen
stay standing.
::

The namespace is what keeps the two sides apart. The aliases used to be the short
names (`plus`, `calendar`…), and back then installing rform meant defining 16
aliases **in your app** — an `<Icon name="plus" />` on a page of yours resolved to
the icon the module picked, and a `calendar` alias of your own **replaced** the
`RDate` icon with nobody asking.

## Per component or per tag

The alias holds for the whole app, and for every component that uses that icon.
Every field and every util that draws an icon also has the `icons` prop, keyed by
the icon's **role**, not by its drawing: `RNumber` has `decrement` and `increment`,
not `minus` and `plus`. The value is the raw iconify name.

There are three layers, and the lower one wins:

| layer                                             | reach                                         |
| ------------------------------------------------- | --------------------------------------------- |
| the component's `defaults.icons`                  | the default, which reads the `rform:` aliases |
| `defineFieldDefaults`, in `app/rform/defaults.ts` | that component, across the whole app          |
| the prop on the tag                               | that one tag                                  |

```ts
// app/rform/defaults.ts
import { defineFieldDefaults } from "#rform/utils";

export default defineFieldDefaults({
    Number: { icons: { increment: "lucide:plus", decrement: "lucide:minus" } },
    Utils: { Error: { icons: { alert: "lucide:circle-alert" } } }
});
```

```vue
<template>
    <RNumber
        name="quantity"
        :icons="{ increment: 'lucide:circle-plus' }"
    />
</template>
```

A role you do not write keeps its default, and `""` leaves that role without an
icon — `Utils: { Error: { icons: { alert: "" } } }` removes the icon from every
error message.

**On a field, `icons` has the shape of `ui`**: the field's own roles at the top,
and those of the utils it renders under `Utils.<Name>`. That is where the util
reads from, and the only place — so
`<RText :icons="{ Utils: { Error: { alert: 'lucide:circle-alert' } } }">` swaps that
field's error icon. A field's own role never comes down: an `RSelect`'s `loading`
is the panel's, and the spinner of its `RUtilsLoading` is
`Utils.Loading.loading`. A bare `alert` in a field's `icons` does not compile and
does nothing.

For a util's icon there are four layers, and the lower one wins:

| where                                                                       | reach                        |
| --------------------------------------------------------------------------- | ---------------------------- |
| the util's `defaults.icons`                                                 | the default                  |
| `defineFieldDefaults({ Utils: { Error: { icons: { alert } } } })`           | that util, in every field    |
| `defineFieldDefaults({ Text: { icons: { Utils: { Error: { alert } } } } })` | that util, inside that field |
| the prop on the tag                                                         | that tag only                |

The roles of each component:

| component        | roles                                                          |
| ---------------- | -------------------------------------------------------------- |
| `RNumber`        | `decrement`, `increment`                                       |
| `RArray`         | `add`, `remove`                                                |
| `RCheckbox`      | `check`                                                        |
| `RDate`          | `calendar`, and `Utils.Calendar.prev`/`next`                   |
| `RSelect`        | `clear`, `toggle`, `search`, `loading`, `failed`               |
| `RFile`          | `upload`, `loading`, and `Utils.FileItem.*` for the row        |
| `RSwitch`        | `on`, `off` (empty by default), `loading`                      |
| `RPassword`      | `generate`, `show`, `hide`, `idle`, `pending`, `met`, `failed` |
| `RUtilsLoading`  | `loading`                                                      |
| `RUtilsError`    | `alert`                                                        |
| `RUtilsCalendar` | `prev`, `next`                                                 |
| `RUtilsFileItem` | `file`, `failed`, `retry`, `cancel`, `remove`                  |

::callout{type="warn"}
Two old forms are gone. On `RSwitch`, the `:icon="{ true, false, loading }"` object
became `:icons="{ on, off, loading }"`, and the `icon` prop is gone — turning the
indicator off is `""` on all three roles, `:icons="{ on: '', off: '', loading: '' }"`.
On `RUtilsError`, `ui.icon.name` became
`icons.alert`, and `ui.icon` is now the class string that used to be
`ui.icon.class`.
::

## In your own fields

In a `.vue` under `app/rform/fields` or `app/rform/utils` you write the iconify
name directly, as in any Vue component. But if the icon is one of the 20, write the
**alias**: besides not repeating the name, it **follows any override** the app has
made.

```vue
<template>
    <Icon name="rform:alert" />
    <Icon name="fa6-solid:star" />
</template>
```

For your component to get the `icons` prop, it follows the same convention as the
built-ins: `defaults.icons` declares the roles, `Props` intersects
`IconsProp<typeof defaults.icons>`, and the template reads `props.icons.<role>`. The
three layers and the inheritance through utils then come for free.

In `defaults.icons` the name is **short**, like a `defaults.text` key: the module
adds the `rform:` prefix itself, so `hint: "alert"` becomes `rform:alert`. A name
with a `:` (`"lucide:star"`, or `"rform:alert"` spelled out) and `""` pass
through untouched. Only the component's own `defaults` is prefixed — what the app
writes on a tag or in `defineFieldDefaults` is still an iconify name.

```vue
<template>
    <Icon :name="props.icons.hint" />
</template>

<script lang="ts">
    import type { DeepPartial, IconsProp } from "#rform/types";
    import { defineDefaults } from "#rform/utils";

    export const defaults = defineDefaults({
        ui: { icon: "shrink-0" },
        icons: { hint: "alert" }
    });

    export type Props = {
        ui?: DeepPartial<typeof defaults.ui>;
    } & IconsProp<typeof defaults.icons>;
</script>
```

The full example is `RUtilsHint`, in
[Your own fields](/en/concepts/campos-proprios#a-util-the-module-does-not-have).

::callout{type="warn"}
A name that is not one of the 20 and has no `:` renders **nothing** — just an
`[Icon] failed to load icon` in the console. That is the failure mode to know: a
typo'd `hint: "plux"` breaks neither the build nor lint, it erases the icon.
::

## The guard

`test/unit/icons.test.ts` covers three cases, because a wrong name breaks neither
build nor lint — it just erases the icon: (a) the
set of short names in the components' `defaults.icons` **equals** the declared aliases, in both
directions; (b) no static name without a `:` was left in a template — which is
exactly what erased four icons when the namespace landed; (c) the prefix the runtime
applies and the module's short name are the same string.
