Every visual layer of a field has a name, and every name can be overridden. This
page shows the whole chain: what the component declares, what your defaults file
changes, and what the prop at the call site decides.

## The precedence chain

The three go through the same `merger`, in this order — and whoever comes later
wins:

| #   | when      | what                                                                             |
| --- | --------- | -------------------------------------------------------------------------------- |
| 1   | component | `defineDefaults` — the `ui` and the `default` `RText` declares in its own file   |
| 2   | project   | `app/rform/defaults.ts` — `defineFieldDefaults`, per component name and per Util |
| 3   | field     | `:ui="{ … }"` — the prop at the call site. Last in line, so it decides           |

## ui at the call site

The `ui` prop is a `DeepPartial`: you write only the layer you want to change.
And what joins the classes is **tailwind-merge**, so `p-6` replaces the default's
`p-3` without taking the rest of the layer with it — the focus ring is still
there.

## null clears the layer

`undefined` means "I did not pass anything", and is skipped. `null` is explicit:
it zeroes that layer's classes. An empty string will not do, because
tailwind-merge joins and the default survives.

::

::callout{type="warn"}
Today this needs a cast: `mergerUI` understands `null`, but the type of `ui`
only admits `string | undefined`.

## ui.Utils — the field commanding the Util

`Label`, `Placeholder`, `Description`, `Error`, `Length` and `Loading` are
separate components with `defaults` of their own. The `Utils` block inside the
field's `ui` reaches each of them, and only on that field.

## app/rform/defaults.ts

One optional file, keyed by component name: it is where the project decides what
every `RText` looks like, without repeating a prop on a single field. The `Utils`
block at the top does the same for the sub-components, globally.

```ts
import { defineFieldDefaults } from "#rform/utils";

export default defineFieldDefaults({
    Text: {
        ui: {
            container: "gap-2",
            group: {
                field: {
                    input: "p-4 text-base"
                }
            }
        },
        default: ""
    },
    Utils: {
        Placeholder: {
            ui: {
                default: "text-xs"
            }
        }
    }
});
```

The module generates an empty template when the file does not exist — so creating
it later works, and this site runs **without** it on purpose, so the pages show
the real default.

### Four things that bite

- **tailwind-merge, not concatenation.** A new class only removes the old one when
  the two fight over the same property. Passing `p-6` swaps the padding and keeps
  the rest of the layer.
- **`null` zeroes, `undefined` skips.** `undefined` is "I did not pass anything"
  and the merger skips it; `null` is explicit and erases the layer's classes.
- **Global `Utils` vs the field's `ui.Utils`.** `Utils` at the top of the file
  applies to everyone; `ui.Utils` inside a field applies only there — and beats
  the global one.
- **The helper's name is an agreement, not a detail.** `defineFieldDefaults` is
  written into `oxlint.config.ts` and `.vscode/settings.json`. Renaming it
  without touching both makes class linting and IntelliSense stop **silently**
  inside the file.

## The other side: defineDefaults

This is what each module component calls to declare what you just overrode: the
complete `ui` plus the model's initial value. `Element<typeof defaults>` types the
props from there — which is why the type of `modelValue` comes out of `default`.

```ts
export const defaults = defineDefaults({
    ui: {
        container: "flex w-full flex-col gap-1",
        group: {
            wrapper: {
                container: "relative z-0 flex w-full flex-row items-center rounded-xl …",
                leading: "p-3 pr-0 flex",
                trailing: "p-3 pl-0 flex"
            },
            field: {
                container: "relative grow",
                input: "w-full rounded-lg bg-transparent outline-none p-3"
            }
        }
    },
    default: ""
});

export type Props = Element<typeof defaults, "text"> & Utils["Placeholder"] & Utils["Error"];
```

The root `container` is `w-full`, not `grow`. A field's natural parent is the
`RForm`, which is a column, and growing there means growing in **height**: in a
fixed-height panel every field would get an empty gap below it. For a field that
should take the leftover height, ask for it at the call site —
`:ui="{ container: 'grow' }"`, which tailwind-merge adds to the `w-full`.

## The hook classes

Every field and every util — built in **and** yours — carries two classes at its
root:

| root                          | generic  | specific                                   |
| ----------------------------- | -------- | ------------------------------------------ |
| `fields/`, `app/rform/fields` | `RField` | `R<Name>` — `RField RText`                 |
| `utils/`, `app/rform/utils`   | `RUtil`  | `RUtils<Name>` — `RUtil RUtilsPlaceholder` |

The specific one mirrors the tag you write. They are the target of the module's
resets — and that is why they do not depend on an `RForm` ancestor.

What writes them is `hookUi`, **after** the merge: `ui` is overridable by
contract, and a hook declared in `defaults` would leave along with a
`ui: { container: null }`.
