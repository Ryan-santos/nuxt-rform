A `.vue` file in `app/rform/fields` is a **first-class** field: it gets an
`R`-prefixed tag, enters `FieldType` (so `useRForm` accepts the `type`),
`Components` (so `defineFieldDefaults` types it) and can be the target of a
preset's `available`. `app/rform/utils` does the same for the field's inner
pieces.

## A field the module does not have

```vue
<template>
    <div :class="props.ui?.container">
        <RUtilsLabel />

        <div :class="props.ui?.group">
            <button
                v-for="star in props.max"
                :key="star"
                type="button"
                :class="[
                    props.ui?.star?.base,
                    star <= current ? props.ui?.star?.on : props.ui?.star?.off
                ]"
                @click="model = star"
            >
                <Icon name="fa6-solid:star" />
            </button>
        </div>

        <RUtilsHint />
        <RUtilsDescription />
        <RUtilsError />
    </div>
</template>

<script lang="ts">
    import { computed } from "vue";

    import { useField } from "#rform/composables";
    import type { Element } from "#rform/types";
    import type Utils from "#rform/types/components/utils/props";
    import { defineDefaults } from "#rform/utils";

    export const defaults = defineDefaults({
        ui: {
            container: "flex grow flex-col gap-1",
            group: "flex w-fit flex-row gap-1 rounded-xl bg-background-100 p-2",
            star: {
                base: "cursor-pointer rounded-md p-1 text-xl transition-colors",
                on: "text-warn",
                off: "text-contrast/20 hover:text-contrast/40"
            }
        },
        default: 0,
        max: 5
    });

    export type Props = Element<typeof defaults, "rating"> &
        Utils["Label"] &
        Utils["Description"] &
        Utils["Error"] &
        Utils["Hint"] & {
            max?: number;
        };
</script>

<script setup lang="ts">
    const _props = withDefaults(defineProps<Props>(), {
        required: undefined,
        loading: undefined
    });

    const { model, props } = useField(_props);

    const current = computed(() => Number(model.value ?? 0));
</script>
```

From then on it is a field like any other — `name`, `rule`, `label`, `ui` and
the model work with nothing extra.

## A util the module does not have

`app/rform/utils/Hint.vue` becomes `RUtilsHint` and sees the parent field's props
through `useUtil`, just like `RUtilsError`. The `Rating` above renders it, so the
`hint` prop starts existing on any field that includes it.

```vue
<script lang="ts">
    import { useUtil } from "#rform/composables";
    import type { DeepPartial } from "#rform/types";
    import { defineDefaults, icon } from "#rform/utils";

    export const defaults = defineDefaults({
        hint: "",
        ui: {
            container: "ml-1 flex flex-row items-center gap-1 text-xs text-current/50",
            icon: { name: icon("alert"), class: "shrink-0" }
        }
    });

    export type Props = {
        hint?: string;
        ui?: DeepPartial<typeof defaults.ui>;
    };
</script>

<script setup lang="ts">
    const { props } = useUtil<Props>();
</script>
```

::demo{src="Customizados/util-novo" title="RUtilsHint, a util of the app"}
::

`icon` from `#rform/utils` is what makes the `alert` here the **same** icon
`RUtilsError` uses — and follow any override the app made to it. For an icon that is
only yours, write the iconify name directly, the way `Rating` does with
`fa6-solid:star`. See [Theme](/en/concepts/tema#in-your-own-fields).

## In a useRForm schema

Because the field enters `FieldType`, it is a valid `type` in a schema — and
`RDynamic` builds it on its own, with no tag written by hand.

## In defineFieldDefaults

`app/rform/defaults.ts` is typed from the same `Components`, so the new field
shows up in it with autocomplete:

```ts
import { defineFieldDefaults } from "#rform/utils";

export default defineFieldDefaults({
    Rating: {
        max: 10,
        ui: { star: { on: "text-primary" } }
    },
    Utils: {
        Hint: { ui: { container: "text-[10px]" } }
    }
});
```

## Replacing a built-in

**The same name replaces the whole built-in** — the same precedence as presets.
To **wrap** instead of rewrite, the original stays reachable through the
`#rform/builtin` alias:

```ts
import Base, { defaults as base } from "#rform/builtin/fields/Text.vue";
```

::callout{type="warn"}
`Form` and `Dynamic` are **reserved** names. An `app/rform/fields/Form.vue` fails
the build naming the file.
::

## Rules for the file

- Alphanumeric PascalCase name — it becomes an object key **and** a `FieldType`
  member.
- `<script>` exports `defaults` (via `defineDefaults`) and the `Props` type.
- A field calls `useField(_props)`; a util calls `useUtil<Props>()`. You never write
  the `defaults` or the component name: the build injects both into the call.
- Containers (those that accept children) also call `useProvide({ id, model })`.
- A native `<input>`/`<textarea>` binds through `:value` + `@input`, **never
  `v-model`** — see below.

## The native element binds through `:value` + `@input`

```vue
<template>
    <input
        :value="model"
        @input="model = inputValue($event)"
    />
    <input
        type="checkbox"
        :checked="model"
        @change="model = inputChecked($event)"
    />
</template>
```

`inputValue` and `inputChecked` come from `#rform/utils` and only hide the
`$event.target` cast. The reason it is not `v-model`: the directive's `mounted`
is a post-render effect that a still-pending `<Suspense>` holds back — the
`NuxtPage` page with a `lazy` `useFetch` filling the model, for instance. When
it resolves, it reapplies the value from **mount time** over whatever arrived in
between, and the field shows up empty with the model right. With `:value` the
value is a prop, patched in place, with no deferred hook. Every built-in field is
written this way.
